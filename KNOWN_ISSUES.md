# Known issues

Bugs and limitations tracked against the [issue tracker](https://github.com/aallan/vera/issues). This file is a curated snapshot; the issue tracker is the source of truth, and priority and sequencing live in [ROADMAP.md](ROADMAP.md). Each row says what the issue is, then its impact and the path forward.

## Bugs

Defects in shipped compiler, runtime, or tooling behaviour. This table matches the issue tracker's open [`bug`-labelled issues](https://github.com/aallan/vera/issues?q=is%3Aissue%20state%3Aopen%20label%3Abug) one-to-one, and the [milestones](https://github.com/aallan/vera/milestones) show the release each one is assigned to. A silent defect (a wrong value, a wrong proof, or a wrong program accepted, with every gate green) carries the `soundness` label beside `bug`; verification incompleteness that fails closed, a proof left to a runtime check or a shape refused rather than miscompiled, carries `limitation` and is tracked under [Limitations](#limitations). A defect in the test suite, CI, the language server or the documentation carries `testing`, `ci`, `lsp` or `documentation` without `bug`, and is not listed here.

## Limitations

| Nested handlers over the same `State<T>` (nesting over different families is unaffected) cannot honour spec §7.5.2's enclosing-context rule for a clause-body bare `get`/`put`. The lowering routes the operation outward correctly, but the host cell intrinsics (`state_get_T` / `state_put_T`) address only the innermost pushed cell of a family, so the operation would read or write the inner cell where the rule names an outer one, at a distance too, as in an `Int`/`Nat`/`Int`/`Nat` nest whose third level routes to the second. The shape is refused at check time (`E339`) where the operation is written, rather than lowered to hybrid semantics; a cell named by a type parameter is refused wherever an instantiation can make it the same family, so a generic `State<T>` nested in a `State<Int>` is refused at `T = Bool` too. The fix is depth-indexed host access (`state_get_at`/`state_put_at` or push-time cell handles) across the native, browser and WASI hosts, plus the verifier's obligation keying for depth-addressed cells. Outward clause re-entry is separately capped at 8 levels (`STATE_CLAUSE_INLINE_DEPTH_CAP`), because each re-entry re-expands another clause body and the emitted code is exponential in the nesting depth; a deeper chain is refused at check time too (`E339`). | [#1233](https://github.com/aallan/vera/issues/1233) |
| An ADT `decreases` measure is ranked at run time only when its type's reachable field structure is fully concrete. A parameterized measure (`List<Int>`), or a concrete type whose recursion passes through a parameterized field, gets no runtime guard, because the registered generic layout does not describe concrete construction (no guard is emitted rather than a wrong one): Z3 still checks it, and where Z3 cannot prove it the obligation is reported as unguarded (`E543`). Per-instantiation `$dec_size_<T>` helpers (the `$eq_<type>` pattern) close it. A generic `where` helper on a recursion cycle with its generic parent leaves its own `decreases` at `tier3` (`E525`), though every call on the cycle decreases and the parent's is proved.  That case fails closed: the measure is checked at run time. | [#1561](https://github.com/aallan/vera/issues/1561) |

| Contracts that depend on a `handle[...]` expression's value fall to Tier 3 unless every clause is exactly `{ resume(x) }` in tail position and no operation the body performs has a refined result type, in which case the handle has its body's value. | Every `vera` invocation re-parses and re-checks the whole module graph from scratch.
