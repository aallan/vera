# Known issues

Bugs and limitations tracked against the [issue tracker](https://github.com/aallan/vera/issues). This file is a curated snapshot — the issue tracker is the source of truth, and priority/sequencing live in [ROADMAP.md](ROADMAP.md). Every row follows the same shape: one sentence on what the issue is, one sentence on impact and the path forward.

## Bugs

Defects in shipped compiler, runtime, or tooling behaviour — this table matches the issue tracker's open [`bug`-labelled issues](https://github.com/aallan/vera/issues?q=is%3Aissue%20state%3Aopen%20label%3Abug) one-to-one, and the [milestones](https://github.com/aallan/vera/milestones) show the release each one is assigned to. A verification-soundness defect (a proof or a clean verify that the running program contradicts, or a runtime check verify claims and code generation does not emit) carries the `soundness` label beside `bug`; verification incompleteness that fails closed, a proof left to a runtime check or a shape refused rather than miscompiled, carries `limitation` and is tracked under [Limitations](#limitations). A defect in the test suite, CI, the language server or the documentation carries `testing`, `ci`, `lsp` or `documentation` without `bug`, and is not listed here.

## Limitations

| `vera verify --reconcile` cannot tell a partial set of component checks from a whole one where the verifier records one obligation for a whole value it cannot see into (an opaque argument of a tuple-typed parameter): any one of the value's component checks answers that record, because only code generation's decomposition states which components are guarded. | [#1642](https://github.com/aallan/vera/issues/1642) |
| Nested handlers over the SAME `State<T>` cannot honour spec §7.5.2's enclosing-context rule for a clause-body bare `get`/`put`. The clause TRANSFORM half routes outward correctly, but the host cell intrinsics (`state_get_T` / `state_put_T`) address only the innermost pushed cell of a family, so the operation would read or write the INNER cell where the rule names an outer one — including at a distance, as in an `Int`/`Nat`/`Int`/`Nat` nest whose third level routes to the second. The shape is refused at check time (`E339`) where the operation is written, rather than lowered to hybrid semantics; a cell named by a type parameter is refused wherever an instantiation can make it the same family, so a generic `State<T>` nested in a `State<Int>` is refused at `T = Bool` too. Different-family nesting is unaffected. Outward clause re-entry is separately capped at 8 levels (`STATE_CLAUSE_INLINE_DEPTH_CAP`), because each re-entry re-expands another clause body and the emitted code is exponential in the nesting depth; a deeper chain is refused at check time too (`E339`). | [#1233](https://github.com/aallan/vera/issues/1233) |
| An ADT `decreases` measure is runtime-ranked only when its type's reachable field structure is fully concrete: a parameterized measure (`List<Int>`), or a concrete type whose recursion rides through a parameterized field, gets no runtime guard (never a wrong one — the registered generic layout does not describe concrete construction), staying statically checked and Tier-3-disclosed.
