- **A nightly mutation sweep measures all of `vera/`, a slice a night** ([#795](https://github.com/aallan/vera/issues/795); `scripts/mutate_sweep.py`, `tests/test_mutate_sweep.py`, `.github/workflows/mutation-nightly.yml`).  mutmut makes about 110,000 mutants of the 2,371 functions it mutates in `vera/`, and no single run holds them: the local marathon deadlocked four times under Python 3.14.  Each night seven jobs plan the same night from the state the last night left: the undecided work in the tree's order, in one bin a job of a 4.5 h budget, a function whose mutant count is known split across bins by its mutants' numbers and one not yet generated taken whole.  Each job runs its bin through the diff lane's machinery, in a scratch tree narrowed to the bin's functions, with the whole tree in mutmut's copy and every test file the lane's rule admits as the oracle.  A stitch job folds the slices into the state, kept as the `mutation-sweep-state` artifact for 90 days, keyed by each function's code hash, so a function that changes is measured again.  When every function's every mutant is decided, the cycle closes, and `python scripts/mutate_sweep.py summary` writes its `mutation-summary.csv` and the README badge's `mutation.json` for a pull request to commit.  A scheduled night that decides nothing, or whose engine or lane fails, files or updates one tracking issue (`mutation-sweep`); survivors never do.
  - `scripts/mutate_diff.py`'s drop of a test that fails inside mutmut's copy is shared with the sweep (`run_dropping`), and its config rewrite can replace `also_copy`.
