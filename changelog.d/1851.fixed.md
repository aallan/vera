- A tail-recursive function with a postcondition or a refined return type runs at constant stack depth ([#1851](https://github.com/aallan/vera/issues/1851)).  An `ensures` is checked where a function returns to its caller: a function with a check after its body that calls itself in tail position compiles as an entry, which calls the body once and runs the check on what it returns, and a body, whose self tail calls transfer to the body.  `count_proved`, whose `ensures(@Nat.result >= 0)` is proved, exhausted the call stack at 50,000 steps and now runs a million, as its `ensures(true)` twin does; a loop whose postcondition is checked at run time, a refined return, `old` and `new` state, a `where` helper and a loop that allocates on every hop do too.  Preconditions, refined parameters and the `decreases` measure are still checked on every hop, and a self call that is not in tail position is checked when it returns.  What is given up: a step inside the loop whose own instance of the postcondition fails no longer traps when the loop's answer satisfies the postcondition at the caller's arguments; a direct call at that step's arguments still does.  Mutual recursion stays bounded by the call stack.  The `stack_exhausted` trap's Fix paragraph says what still costs a tail call, and the spec states the rule (§5.6.1, §6.2.2, §11.8.3, §11.8.4).
