- **A negative component no longer reaches a `@Nat` component through a composite coercion** ([#1542](https://github.com/aallan/vera/issues/1542), [#1695](https://github.com/aallan/vera/issues/1695)).  The checker admits a value whose type holds an `@Int` where its position's type holds a `@Nat`: an `Option<Int>` at an `Option<Nat>` formal, `let @Option<Nat> = @Option<Int>.0`, a `W(@Int.0)` inside an array literal bound at `Array<Wrap<Nat>>`, a binder declared `Tuple<Int, Nat>` over a `Tuple<Int, Int>` field, a map key or value or a set element.  Nothing obligates the component, and v0.2.6 guarded it nowhere, so `vera verify` passed and `vera run` returned a negative from a `@Nat` function; v0.2.5 had trapped most of these positions only through guards placed on the read side by accident.  Code generation now guards every such component by one rule over the typed program: a construction's component where it is stored, an opaque value (a slot, a call's result, an index, a field read) by a walk of every differing component (`Some`, the differing side of a `Result`, a tuple's or a record's field, every constructor's field of a data type, every element of an `Array`, every key, value or element of a `Map` or `Set`, a `Future`'s payload), and a pattern binder, a destructure or a handler clause binder declared narrower than what it binds by a walk of the bound value.  A negative component traps as a scalar narrowing does, `Negative value bound into a @Nat slot` (`E800` at `vera run`).  A store's in-place guard, a nested literal's hand-down and a function boundary's tuple-component guard stand where they stood, and the rule adds none beside them.  `vera verify` reports each new guard as `W004` (a check with no record) until the obligation table ([#1695](https://github.com/aallan/vera/issues/1695)) records the coercion.  A `Map` or `Set` coercion's guard reads the collection through the same projections `map_keys`, `map_values` and `set_to_array` use, so it is O(n) in the collection's size and allocates.  Two positions stay unguarded and disclosed: a handler clause binder over an `Array`, `Map` or `Set` payload keeps its `E506`, and a function type gaining a `@Nat` component (`fn(Int -> Int)` at `fn(Int -> Nat)`) has no value a walk can read where the function is passed ([#1819](https://github.com/aallan/vera/issues/1819): v0.3.0 refuses it).
