- **Breaking: a construction passed to a call is modelled as any argument is, so a postcondition its callee's contract does not establish is refused** ([#1525](https://github.com/aallan/vera/issues/1525)).  The verifier gave a construction a sort only where the function named its type in its signature or in an earlier `let`, so a `main` whose `ensures(@Int.result == 2)` rested on `color_code(Green)`, under `color_code`'s `ensures(true)`, fell to a runtime check (`E522`), while the same call over an `@Int` was refused.  A construction is now a term of the sort of its checked type (Fixed, below), and since the verifier is modular (spec §6.4.2), a claim the callee's contract does not make has a counterexample and is refused with `E500`, as DESIGN.md's pipeline refuses every satisfiable negation.  Upgrade: state the value in the callee's `ensures`, `ensures(match @Color.0 { Red -> @Int.result == 1, Green -> @Int.result == 2, Blue -> @Int.result == 3 })`.  A value a recursion computes cannot be stated there, since a contract may not call its own function or a mutual partner (`E138`, spec §6.3.1), so a caller that pins one keeps it as an `assert`, which is checked at run time as the `ensures` was.  An equality between a data type at `Nat` and the same at `Int` is a runtime check where a side reads a parameter's or an opaque result's value, through a `@Nat` binder too, since such a value states no `>= 0` of its `Nat` components ([#1814](https://github.com/aallan/vera/issues/1814)): `mk(@Nat.0) == Some(nat_to_int(@Nat.0))` under `mk`'s `ensures`, which was proved, is one now, and so is `@Box<Nat>.0 == MkBox(@Int.0)`, which was refused with `E500` and the counterexample `MkBox(-1)`.  Eight conformance programs pinned such a value and are rewritten so: five give the callee the `ensures`, three keep the value as an `assert`; their output is unchanged, and no example or documentation example moves.
- **The verifier reads every type from the typed program and derives none** ([#1525](https://github.com/aallan/vera/issues/1525)).  A parameter's, a return's, a `let`'s, a binder's, a field's, an operation's, a cell's and an alias's declared type is the type the checker resolved its type expression to, and a generic instance's type arguments are its instance's; `ContractVerifier._resolve_type` and the verifier's alias resolution are deleted.  A construction's sort is the sort of the type the checker gave it, whatever file declares the type, and `Nat` and `Int` are one sort, as a refinement and its base are; the recovery of a constructor's instantiation from its arguments' sorts, the selection among the sorts already built and the forced parameter sorts are deleted.  Code generation guards a `@Nat` pattern binder and destructure component where the verifier records a narrowing, reading the component's sources as the verifier does (`vera.narrowing.component_narrows`), so the binder of `match Some(5) { Some(@Nat) -> … }` and the `5` of `let Tuple<@Nat, @Nat> = Tuple(@Int.0, 5)` hold no `nat_guard`.  Over the 323 corpus programs the obligation stream moves in 12, each move a runtime check that now proves (25 in all), and WAT in one, which loses a destructured `5`'s guard; the reconciliation join's known mismatches go from 33 to 32.
