- **A call argument whose type leaves a type variable open takes one type for it, and a function compiled before its variable had a type fits no other** (the call-argument line of [#1684](https://github.com/aallan/vera/issues/1684)).  The argument judgement (`CallsMixin._fits`) matched each open variable as a wildcard, one position at a time, so a value of type `Tuple<Option<T>, Option<T>>` fitted a `Tuple<Option<Int>, Option<String>>` parameter, and the identity closure `fn(T -> T)` from a call no argument of which fixes `T`, which code generation compiles at a type of its own, fitted `fn(Option<Nat> -> Option<String>)` and ran with a `Nat` read as a `String`, or trapped against `fn(Int -> Int)`; the closure from `mk2([])`, whose `T` is an empty literal's element type, fitted `fn(Array<Nat> -> Array<String>)` the same way ([#1692](https://github.com/aallan/vera/issues/1692)).  A generic call's result also took the data type its context expected on the type's name and arity alone (`_synth_fn_call`), before the judgement saw it: a data value holding such a closure fitted any instantiation of its type, an `if` gave `twice(None)` the other branch's `Tuple<Option<Int>, Option<String>>` ([#1690](https://github.com/aallan/vera/issues/1690)), and in a `forall<A>` body `Two<A, A>` passed as a `Two<Int, Int>`, so `g(true)` printed 68719476737.  Both now ask the join an array literal's elements and an `if`'s and a `match`'s arms are given ([#1668](https://github.com/aallan/vera/issues/1668)): each open variable is bound once by name, one in a function type or in a data field held over one is not open, and the enclosing function's own are rigid.  `E202` names the variable, its two positions and the two types the parameter gives it, or, for a function compiled at its own type, the closure to write in place of the call; a built-in's variable a failed substitution lost keeps the verdict it had ([#1688](https://github.com/aallan/vera/issues/1688)).  An array literal's element is held to the literal's element type by the same judgement, so an element that would give such a closure's variable a type is refused (`E162`), as an `if`'s branch and a `match`'s arm already were.  No example, conformance program or documentation example changes verdict.
