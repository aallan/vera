- **A fix that tells the reader to write a type writes it as the program does** ([#1778](https://github.com/aallan/vera/issues/1778)).  A type a fix named was rendered in the message form, which elides a refinement's predicate, so under `type Pos = { @Int | @Int.0 > 0 }` the `E336` fix for `handle[State<Pos>](@Int = 1)` said to declare the state as `@{@Int | ...}`, which does not parse; it now says `` `@Pos` ``, and `E202`'s fix for a `Bool` passed at a `@Pos` parameter names `` `{ @Int | @Int.0 > 0 }` ``.  Every fix that names a type or an effect row writes it through the one renderer of a type as written (`vera.types.written_type`, by `ast.format_type`): `E122`, `E125`, `E162`, `E170`, `E171`, `E201`, `E202`, `E204`, `E213`, `E241`, `E301`, `E302`, `E313`, `E314`, `E320`, `E321`, `E331`, `E334`, `E335`, `E336`, `E340`, `E341`, `E533` and `W001`; each but `W001`'s, whose type names the expression to write, is a backticked span to paste.  A refinement keeps its predicate, and one whose predicate names its binder by an alias (`type Count = Nat; type Pos = { @Count | @Count.0 > 0 };`) is written over that alias, `{ @Count | @Count.0 > 0 }`, where its base resolved to `Nat` would leave the predicate's `@Count.0` unbound (`E130`).  A type with a part no program writes, a type variable no argument fixed (`fn(? -> ?)`), is not named: `E301` converts to the other branch's type, and `E162` names the element type it can.
- **A fix's example is computed from the site** ([#1763](https://github.com/aallan/vera/issues/1763)).  A fix written as a literal example named a slot or a shape the site may not have: `E503`'s `requires(@Int.0 >= 0)` in a function with no `@Int` is refused (`E130`) when written.  `E503`, and `E502` outside a `decreases` measure, now offer a precondition over the narrowed value or the subtraction's operands where those read at the function's entry as they do at the site (a division only by a non-zero literal), or over one parameter the counterexample names (a numeric one before a `Bool`, whose clause could make the narrowing branch dead), and only one the solver confirms discharges the obligation, within the run's per-query budget: the reported `sentinel` gets `` `requires(@Bool.0)` ``.  `E123`, `E124`, `E126` and `E300` compare the site's own operand with zero, written by the canonical formatter so a grouped operand keeps its parentheses; `E127` and `E137` measure the function's own `Nat`, `Int`, data-type or array parameter; `E128` passes the array's own length; `E201` and `E202` apply a function value in scope at the site; `E216` writes one element per component the site expects; `E321` writes a binding per field at its type; `E337` keeps the handler's own type argument; and `E340`'s handler fix aliases the site's own type argument, where the argument names none of the function's type parameters, its description naming the shape written (a function type, not "an inline refinement").  `E040`'s example names its operand `a`, where it named `@Int.0`, and `E323`'s and `E333`'s fixes are the sentence alone, without the literal example each gave.  Where nothing can be computed, the sentence stands without an example.  `E024` on a file that begins with a UTF-8 byte-order mark gives a command that drops the mark before converting (`tail -c +4 marked.vera | iconv -f ISO-8859-1 -t UTF-8 > marked.utf8.vera`), where the old one wrote the mark into the copy as `ï»¿`, which `vera check` refused (`E006`).
