- **Each pull request writes its CHANGELOG entry as a fragment under `changelog.d/`, and the release pull request assembles them** ([#1529](https://github.com/aallan/vera/issues/1529)).  A fragment is `changelog.d/<issue>.<section>.md`, or `changelog.d/+<slug>.<section>.md` for a pull request that closes no issue, and holds its bullets exactly as `CHANGELOG.md` will carry them, so two pull requests no longer edit the same `[Unreleased]` line and merge in either order.  `python scripts/release.py assemble --version X.Y.Z --date YYYY-MM-DD` writes the release's section from the fragments in Keep a Changelog order, each section's bullets by issue number and then by slug after any bullets still under `[Unreleased]`, writes the compare links and deletes the fragments; two runs over the same fragments write the same bytes.  `scripts/check_changelog_updated.py` accepts a fragment the branch adds as its entry, and `scripts/check_changelog_fragments.py`, in the commit hook and CI's `lint` job, holds every fragment to the name and content rules that `changelog.d/README.md` states.
