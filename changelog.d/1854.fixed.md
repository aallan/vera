- No part of a configured inference API key reaches the `Err` of `Inference.complete` ([#1854](https://github.com/aallan/vera/issues/1854)).  A provider's HTTP error body is read up to 64 KiB, and the read was cut first and redacted after, so a key across the 64 KiB mark left its first part in the message (up to 39 of 40 characters).  So did a credential-shaped token the host was not given (up to `sk-` and seven characters).  Where the read stops, a proper prefix of the key and the start of such a token are now redacted too.  An exception the transport raised was quoted unredacted: a key holding a line end, as one read from a file with CRLF line ends does, reached the `Err` whole (`Invalid header value b'<key>\r\n'`).  Such a key is now refused before any request is built, with an `Err` that names the variable holding it.  An exception's text is redacted and bounded like a provider's, the key as `repr` escapes it included.  The key is matched character by character, each character in any form JSON, Python's `repr` or HTML may give it (`\"`, `\u0026`, `&amp;`), chosen for each occurrence on its own, and where the read stops, its leading characters in those forms are redacted, a cut inside a character's form included.  A key the model name or the provider name holds (`VERA_INFERENCE_MODEL`, `VERA_INFERENCE_PROVIDER`) is redacted too, and so is every other provider's key the host holds, at each cut as well: each redaction removes every key the host holds, before each cut and as the `Err` leaves.  The model name had been quoted whole in every provider message, the key refusal included, and a cut left the first part of a held key of a provider not selected.
