- No part of a configured inference API key reaches the `Err` of `Inference.complete` ([#1854](https://github.com/aallan/vera/issues/1854)).  A provider's HTTP error body is read up to 64 KiB, and the read was cut first and redacted after, so a key across the 64 KiB mark left its first part in the message (up to 39 of 40 characters).  So did a credential-shaped token the host was not given (up to `sk-` and seven characters).  Where the read stops, a proper prefix of the key and the start of such a token are now redacted too.  An exception the transport raised was quoted unredacted: a key holding a line end, as one read from a file with CRLF line ends does, reached the `Err` whole (`Invalid header value b'<key>\r\n'`).  Such a key is now refused before any request is built, with an `Err` that names the variable holding it.  An exception's text is redacted and bounded like a provider's, the key as `repr` escapes it included.
