- The language server publishes a diagnostic located in an imported module on the `import` that brings that module in, with the module's location ahead of its message as `vera check` prints it (`In imported module /path/lib.vera, line 8, column 3: Function 'word' body has type Int, expected String.`), and, for a client that advertises `relatedInformation`, a related location at that line of the module ([#1788](https://github.com/aallan/vera/issues/1788)).  The server placed it at the module's line and column in the importing document, on a line that did not hold what the message named.  A module reached only through another is published on the import of the module that reaches it, and a module that is not UTF-8 (its `E024`) on the import that names it.  Every diagnostic of a module is published, in the compiler's order.
- The language server reads a document with the line-end rule the commands read a file with, so a lone carriage return ends a line, as the protocol counts it ([#1788](https://github.com/aallan/vera/issues/1788)).  A buffer whose line ends were lone carriage returns was handed to the parser as one line, so its diagnostics, tier hints, hover, go-to-definition and completion answered on the wrong line or not at all, and the edit `vera/proposeEdit`, `vera/strengthenContract` and `vera/addEffect` send replaced its first line alone, leaving the rest of the old text after the new.  A CRLF or LF buffer was already read right; a mixed one is now read as `vera check` reads its file, a carriage return inside a string literal included.
