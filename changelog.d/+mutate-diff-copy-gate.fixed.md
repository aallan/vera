- **The mutation lane no longer stops on a test that fails inside mutmut's copy** (`scripts/mutate_diff.py`).  The stats pass runs the selection with `-x` inside mutmut's copy of the tree, where each mutant is a copy of its function, so `test_checker_errors.py`'s collision gate, which runs `scripts/check_diagnostic_fields.py` over `vera/`, read a mutated `vera/checker/core.py` as emitting E121 from 198 sites and failed with no mutant active: a pull request that changed an error-emitting checker function got exit 2 before any mutant ran.  `[tool.mutmut]` deselects that test beside the two that parse `vera/verifier.py`'s text, and the lane drops any other test that stops its stats pass or its clean run that way, runs again, and names it under the table and in the record's `dropped_tests`.
  - A test that starts a Python or `vera` process is skipped inside the copy (`tests/mutation_oracle.py`, a pytest plugin `[tool.mutmut]` loads) and listed in the record's `subprocess_tests`.  Each mutated module there holds a copy of a mutated function for each of its mutants, so every process compiled them afresh (a mutated `TypeEnv._register_builtins` makes `vera/environment.py` 31.7 MB where it is 49 KB, and `vera check` of a one-line program took 2.0 s against 0.5 s), and on a pull request that changed `_register_builtins` and `execute` a CLI test reached its 120 s timeout in the stats pass and stopped the run; the process records nothing for the stats pass, so the test was never a mutant's oracle.
