- **A rule whose answer depends on what a generic is instantiated at is applied at check, at the call that chooses the type arguments** ([#1679](https://github.com/aallan/vera/issues/1679)).  Code generation made four of these judgments per clone, and the verifier a fifth, after `vera check` had accepted the program: an ability constraint the instantiation does not satisfy (`E613`, reported at line 0 with no location), a `State<T>` cell at a type no cell holds (`E607`, the clone and each caller dropped), an `Exn<E>` payload at a type with no representation (`E612`, the same), and a handler whose declared state differs from its cell at the instantiation (`E533` at `vera verify`, and a module that failed to load at `vera compile`).  The check now derives the instances a program needs once, from the type arguments it inferred at each generic call, and refuses each failing one at the root call, the call in a body that is not generic whose type arguments reach it, naming the chain of instances and replacing the call in its fix: `lt(true, false)` under `forall<T where Ord<T>>` reads `The call 'lt(true, false)' instantiates 'lt' at T = Bool, where type 'Bool' does not satisfy ability 'Ord', ...`, fixed by `replace 'lt(true, false)' with 'lt(0, 0)'`.  The codes are kept.
  - A `Map` or `Set` with an `Array` key, value or element is `E135`, as a zero-size one is ([#1680](https://github.com/aallan/vera/issues/1680)): where the type is written, at a map or set operation whose component only inference gives, and at each instance of a generic whose component is a type parameter.  `let @Map<Array<Int>, Int> = map_insert(map_new(), [1, 2], 5)` passed `vera check` and `vera verify`, and code generation dropped its function (`E602`).
  - A generic callee's effect row is read with its type parameters instantiated at the call ([#1769](https://github.com/aallan/vera/issues/1769)): `peek(1)` under `handle[State<Int>]`, for `forall<T> fn peek(@T -> @T) effects(<State<T>>)`, was refused with `E125` (`Function 'peek' requires effects(<State<T>>) but call site only allows effects(<State<Int>>)`), and the contract-purity read (`E187`) took the same row.
  - A generic callee's precondition is checked at the call against its clone's contract, as a monomorphic callee's is ([#1468](https://github.com/aallan/vera/issues/1468)): refuted (`E501`) where it fails, proved where it holds, and demoted (`E532`) only where it cannot be decided.  Every precondition of a generic callee was demoted, a `requires(false)` behind a module boundary and a provable one alike.
- **A generic call is instantiated at what its arguments fix, and runs against that clone** ([#1679](https://github.com/aallan/vera/issues/1679)).  An empty array literal's element type, a type variable of the caller's spelled as one of the callee's, and a callee's variable a nested call left unresolved each bound the callee's variable to nothing, so the call ran against the clone at the phantom `Bool`: `eq_or([], MkBox(1), MkBox(1))` printed `false`, `pick_first([], 5000000000)` failed WASM validation (`type mismatch: expected i32, found i64`), and `wrapped_same(7, 7)`, calling `same(Some(@T.1), Some(@T.0))` with both generics' variable named `T`, compared two heap addresses.  A position an argument's type leaves open is now a hole the arguments beside it fill, and one nothing fills is the phantom, which no value of the arguments holds: `same(empty(()), empty(()))` instantiates `same` at `Option<Bool>` and compares by structure.  A variable a nested call leaves unresolved is a hole from that call's own type on, so renaming a generic's type variable never changes what it instantiates.  `match pick_first([], MkTag("q", Red)) { ... }`, refused with a false `E313`, checks, and a constructor's type is fixed the same way: `second_head(MkTwin([], [5000000000]))`, for `data Twin<T> { MkTwin(Array<T>, Array<T>) }`, read the element at the phantom's width and printed `0`.
- **`E613`'s fix for a type variable no argument fixes names a parameter that carries it** ([#1679](https://github.com/aallan/vera/issues/1679)).  It asked for an annotation of the value the variable is fixed from, and the type a result is bound at fills only a literal's hole, so `let @Option<Int> = none_ord(())` still instantiated `none_ord` at `Bool`.
- **`E135`'s fix replaces the component it refuses** ([#1680](https://github.com/aallan/vera/issues/1680)).  It found the component by its text, so for `Map<Array<Int>, Array<Int>>` the value's fix wrapped the key: `Map<Option<Array<Int>>, Array<Int>>`, itself refused.  It is found by its position in the type as written.
