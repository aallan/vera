- **Breaking: a function value whose result is wider than the function type it reaches is refused at check** ([#1819](https://github.com/aallan/vera/issues/1819)).  A `fn(@Int -> @Int)` closure was accepted where a `fn(Int -> Nat)` or a `fn(Int -> Pos)` was expected, and its result was trusted at the type's: a function declared `-> @Nat` returned -5 with `vera check` and `vera verify` clean, and a `Pos` read back proved later facts at Tier 1 that nothing had checked.  Inside a function type the result now compares by spec §2.8's rules alone, as the parameters do (E189): a closure declared `-> @Int` guarantees no `Nat`.  Declare the closure's result as the position states (`fn(@Int -> @Nat) effects(pure) { ... }`), and its own return is proved or checked; a function value held in a slot is wrapped, `fn(@Int -> @Nat) effects(pure) { apply_fn(@IntToInt.0, @Int.0) }`.  `fn(Int -> Nat)` at `fn(Int -> Int)` and `fn(Int -> Int)` at `fn(Nat -> Int)` are admitted as before.
