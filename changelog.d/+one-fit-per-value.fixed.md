- Inside a generic function, a value passed where the function's own type parameter is required is held to that parameter, as a call's argument is ([#1684](https://github.com/aallan/vera/issues/1684)).  An effect operation's argument (`put(9)` under `handle[State<T>]`), an ability operation's (`eq(@T.0, 9)` under `forall<T where Eq<T>>`), an argument to a callee with no `forall` of its own whose parameter is the outer `T` (`resume(9)` in a `handle[State<T>]` clause, a `where` helper's `helper(9)`) and an argument `apply_fn` passes to a function whose parameter is `T` are refused at check (`E204`, `E241`, `E202`).  `apply_fn` of a value whose type is a bare type variable, the enclosing function's own (`apply_fn(@T.0, 1)`) or one a call left open (`apply_fn(head_plain([]), 1)`), is refused too (`E202`): no function type is there to apply it by.  Each of these passed `vera check` and then failed to load, failed to compile at run, was dropped from the compiled module with `E600`, `E616`, `E602` and `E620` warnings, or drew an internal error from `vera verify` (`E699`).  An argument `apply_fn` passes to a function value whose call gave its type variable no type, `apply_fn(mk(()), 40)`, is refused the same way (`E202`): the function was compiled at a type of its own, and the module did not load.  So is a value whose call left its variable open at an operation's or a call's parameter that is the outer `T` (`put(head_plain([]))` under `handle[State<T>]`, `E204`; `helper(head_plain([]))`, `E202`), which ran only where the open variable's default instance happened to be the right one.  Each refusal's fix names a value of the required type where one is in scope, or the function type to hold the applied value at.
- A destructuring `let` holds its value to its bindings together, so a type variable the value's type leaves open takes one type across them: `let Tuple<@Option<Int>, @Option<String>> = dup(None);`, with `forall<A> fn dup(@A -> @Tuple<A, A>)`, is refused (`E170`) where it checked and ran with `dup`'s one `A` read as `Int` in one binding and `String` in the other.  Such a variable is one no value fixes, so it carries no value, and no wrong value followed.
- Of the programs these refusals reach, only the destructuring `let` above and the open variable at an outer `T` ran; every other one failed to load or to compile, was dropped from the compiled module or drew `E699`.  Over the examples, the conformance programs, the documentation's Vera blocks and generator seeds 0 to 999, every check verdict, verification status, reconciliation report and compiled module is the same as before.
