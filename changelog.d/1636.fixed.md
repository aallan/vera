- A diagnostic names its file, quotes the line it is on and points at its column, from every stage ([#1636](https://github.com/aallan/vera/issues/1636)).  An `E009` (an invalid escape or a malformed interpolation) and an `E040` (a pipe whose right operand is not a call) gave a line and a column and nothing else: the text named no file and quoted no line, `--json` had no `file` and no `source_line`, and an `E013` reporting a module's `E009` named no file for it.  Code generation's `E614` (a typed hole) quoted no line.  Each stage built its location and cut its quote by hand; both are now built by one constructor, and `scripts/check_diagnostic_fields.py` refuses a location or a quote built anywhere else.  A position inside a string literal counts the newlines before it, so a diagnostic in an interpolation after a newline in the literal is on its own line, where it was on the line the literal opens ([#1632](https://github.com/aallan/vera/issues/1632)), and an `E009` is at the escape's backslash or the `\(` that opens the segment, where it was at the literal's opening quote.  `E501`'s `Precondition:` line quotes the clause as `vera fmt` writes it, where it quoted every line the clause spans, whole, with whatever shared them ([#1860](https://github.com/aallan/vera/issues/1860)); `E136`'s copy of a module's alias and `E163`'s spelling of a return type are written the same way.  A fix that names text to replace (`E341`, `E135`, the `apply_fn` fixes) still quotes it as the program writes it, so it can be found and replaced.  **Breaking (text output):** a diagnostic with no position in its file prints `[E900] Error at main.vera:`, where it printed `line 0, column 0` after the file, and one with no file prints `[E901] Error:`, where it printed `Error at line 0, column 0:`; this covers `E800` without a source frame and the command-line refusals `E900` to `E912`.  A consumer that matched the old header text matches `Error at <file>:` or `Error:` instead; `--json` is unchanged for these, with `line` and `column` still 0.
- `vera errors` no longer lists `E003` and `E004`, which no input ever raised ([#1636](https://github.com/aallan/vera/issues/1636)): a malformed slot reference and a missing closing brace are `E005`.  `scripts/check_diagnostic_fields.py` now fails a registered code that no site in `vera/` can raise.
