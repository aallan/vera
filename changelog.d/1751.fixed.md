- **The nightly mutation sweep tolerates a slice whose runner was lost** ([#1751](https://github.com/aallan/vera/issues/1751)).  The nights of 19 and 20 October each lost one of seven slices to a hosted runner taken away under it (GitHub's own annotations on the jobs: lost communication with the server; a shutdown signal, exit 143 at 68 minutes), which uploads no record; the stitch read the missing record as a failure and the night went red with the other six slices' work kept.  A slice with no record is now noted and its work planned again the next night; more than one in a night, or more than three over the last seven nights, still ends the run red.  The sweep job's failure no longer colours the run, the stitch does, and the tracking issue is filed when the stitch fails.  While the engine runs, a slice prints a heartbeat line every five minutes (elapsed time, available memory, swap, load, the engine's last status), so the job log, which outlives a lost runner, carries its resource trail.
- **The Http limitation row no longer says a hung server hangs the program.**  The native runtime gives up after a fixed 60 seconds; what is missing is a caller's control of it ([#351](https://github.com/aallan/vera/issues/351)).
