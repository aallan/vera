- **A test asks a module's record, not its WAT text, whether the module holds a runtime check.**  `tests/pipeline.py` gains `checks()` (and `Compiled.checks()`), which reads `CompileResult.emitted_checks` by trap kind, emitter, obligation, function, path or prelude, and refuses a kind, emitter or obligation no recorded check carries, and a function the module does not define, so a misspelt filter cannot make an absence hold.  The guard-and-trap assertions in `tests/` move onto it, and the WAT text keeps the assertions about how a check is rendered.
  - `scripts/check_record_assertions.py` (pre-commit and CI `lint`) fails a test that reads a check's signal out of the text: a reference to `signal_call_pattern`, `TRAP_SIGNAL` or `CONTRACT_SIGNAL`, a string naming `vera.trap` or `contract_fail` outside a docstring, or a use of a module-level name bound to one.  Its `KEPT` list names each site that stays on the text with its reason, and an entry that names no site fails the gate, so the list only shrinks.
