- **Breaking: a narrowing is no longer proved from the fact its own reader reads** ([#1897](https://github.com/aallan/vera/issues/1897)).  A `match` arm that binds a component takes the component's declared refinement as a fact, read off the scrutinee's declared type.  Where that type was given by a narrowing in the same function (`let @Tuple<Small, Int> = @Tuple<Int, Int>.0`, a constructor field, a tuple component, a store into an array, a `Map` or a `Set`, a `put`, an argument, a return), the fact is the narrowing's own goal, and it was asserted before the narrowing was asked: the narrowing was recorded `verified`, and a payload no check covers reached its reader with every gate green.  A producer's own obligation is now discharged without the fact it publishes (spec §6.2.5, §2.6.4): the narrowing's own obligation is offered the facts a reader takes off the type it gives on no attempt, so a narrowing nothing else proves is refuted (`E505`) or left to its check.  Every other obligation reads those facts where the narrowing is checked at run time (a `@Nat` component, a tuple component at an argument or a return), since the check runs before any reader; where no check covers it (a constructor payload, a tuple component at a `let`), they are withheld as a disclosed producer's are, and an obligation that held only from them is Tier 3 (`E534`, `E532`) with its own check.  A refined tuple component is checked only where code generation takes the tuple apart (a function's or a closure's entry, a return, an argument applied to a function value), so at every other position (a `let`, a branch join, a store, a `State` write or `get` resume, a `throw` payload, a handle's value) its narrowing is now disclosed (`E506`, no check claimed, spec §2.6.5) rather than listed as checked: such a program failed `vera verify` with `E541` and now passes with the warning.  A fact also follows the value it is read from: a value carried on from a narrowing no check covers, through an array literal, a join, a call that returns its argument, a generic identity, a `State` `put` and `get`, a `throw` into a handler clause or a capturing closure, was read at the fresh term the solver made for it as established, and a consumer over it (a callee's `requires`, a `@Nat` binding, an `ensures`) was `verified` though its run trapped.  In a function that holds a narrowing with no check, every term the solver makes for a value is now unestablished unless its lineage is known (an array literal, a built-in other than `apply_fn`), so such a consumer is Tier 3 with its own check; in such a function an obligation over an unrelated call's result can also go to Tier 3.  A narrowing the program proves (from a `requires`, a branch condition or the value's own type) proves as before.  No run changes.
