- **Breaking: a narrowing is no longer proved from the fact its own reader reads** ([#1897](https://github.com/aallan/vera/issues/1897)).  A `match` arm that binds a component takes the component's declared refinement as a fact, read off the scrutinee's declared type.  Where that type was given by a narrowing in the same function (`let @Tuple<Small, Int> = @Tuple<Int, Int>.0`, a constructor field, a tuple component, a store into an array, a `Map` or a `Set`, a `put`, an argument, a return), the fact is the narrowing's own goal, and it was asserted before the narrowing was asked: the narrowing was recorded `verified`, and a payload no check covers reached its reader with every gate green.  A producer's own obligation is now discharged without the fact it publishes (spec §6.2.5, §2.6.4): the narrowing's own obligation is offered the facts a reader takes off the type it gives on no attempt, so a narrowing nothing else proves is refuted (`E505`) or left to its check.  Every other obligation reads those facts where the narrowing is checked at run time (a tuple component at a `let`, an argument, a return), since the check runs before any reader; where no check covers it (a constructor payload, a component below a store), they are withheld as a disclosed producer's are, and an obligation that held only from them is Tier 3 (`E534`, `E532`) with its own check.  A narrowing the program proves (from a `requires`, a branch condition or the value's own type) proves as before.  No run changes.
