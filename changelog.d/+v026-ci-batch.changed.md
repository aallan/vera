- **A release starts when CI's run on the merge commit completes, rather than polling for it** (`.github/workflows/release.yml`).  The workflow runs on `workflow_run` for CI's completed runs on `main`, and its first job goes on only for a successful run of the push event on `main` in this repository, which a fork's pull request whose branch is named `main`, or the nightly run, is not.  It names the commit that run tested, in its job summary beside the CI run, and every later job checks out that commit, builds the archives from it and tags it, where they read the event's own commit, which under `workflow_run` is `main`'s tip when the event fires.  The v0.2.5 release failed at the 100 minutes `scripts/await_ci.py` waited: CI's push run on the release commit took 106, its macOS cells waiting 31 to 70 minutes for a runner, and the failed job was re-run by hand.  A dispatched production recovery, which no CI run starts, still waits for CI's run on its commit, now for at most 180 minutes.  Releases start in the order their merges' CI runs complete, so the GitHub Release is marked Latest only when no higher version is already released.  `tests/test_await_ci.py` holds the trigger, the gate over the 144 combinations of a completed run's conclusion, event, branch and repository, every read of the commit, and the Latest mark, by running the release step under a stand-in `gh`.
- **The `mutation (diff)` lane mutates the lines a pull request changes, not the whole functions that hold them** (`scripts/mutate_diff.py`).  mutmut generates only the mutants whose node starts within two lines of a line the diff adds, or of a point where it removes lines, or on the first line of a call, `match`, assignment, operation, comparison, conditional expression or lambda that spans one of those lines, inside the functions the diff changes: mutmut places a mutant on its node's first line, and those nodes' mutants change text below it, as a call's argument or a `case` (an edit to `error_code="E302",` at `vera/checker/control.py`:430 keeps the argument's `None` and its removal, placed on the call's first line at :419).  The script runs mutmut through itself (`--as-engine`), which counts each function's mutants on every line and in the window with mutmut's own visitor and hands each file's window to mutmut's covered-lines hook; the lane checks the mutants mutmut lists against those counts, and a mutmut without the hook stops the run as an engine failure (exit 2).  Of this cycle's eleven runs with mutants, ten stopped at the 2,400 s budget, four of them before deciding any mutant; an edit inside an existing function keeps 21 to 32% of its mutants in the window ([#1760](https://github.com/aallan/vera/pull/1760)'s 330, of which 97 were decided at the budget, hold 85), and a diff that writes new functions keeps nearly all of theirs.  The job summary names the rule and counts the functions selected, their mutants on every line and in the window, and the mutants generated, decided and surviving.  The budget is unchanged.
- **The budget marker's test allows the float rounding of a deadline read in the tick it was set** ([#1689](https://github.com/aallan/vera/issues/1689)).  `tests/test_budget_marker_1670.py`'s child test reads the budget left as `deadline - time.monotonic()`, where the deadline was `time.monotonic() + seconds`; on a clock that had not advanced between the two reads, as on the Windows runner, that is `(t + 5) - t`, which rounded to `5.000000000000057` and failed the bound `left <= 5`.  The bound allows `1e-6` above, and a cell runs the child's own assertion at a clock sample that rounds the same way.  The same bound failed the `[own-budget-xdist]` case on the Windows runner ([#1771](https://github.com/aallan/vera/issues/1771)): the child stopped at it, with `5.000000000000057`, before its slow stage ran, so the parent found no watchdog header.
- **`scripts/check_wheel_availability.py` says when its interpreter has no `pip`** ([#1743](https://github.com/aallan/vera/issues/1743)).  It runs `python -m pip download` for each dependency and platform, and a virtual environment `uv sync` creates holds no `pip`, so every one of the 36 cells failed there with `No module named pip`, and the script said a platform had lost its wheels.  It checks for `pip` once, before the matrix, and without it stops with one message naming the cause and exit 2, which no lost platform returns.  CI's job runs under an interpreter that has `pip` and is unaffected.
