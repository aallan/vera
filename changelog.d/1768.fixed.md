- `vera test` reports a trial's arguments as the program would write them ([#1768](https://github.com/aallan/vera/issues/1768)).  A `Bool` argument was reported as the `1` or `0` the compiled function receives, a `String` argument was printed without its quotes on the trial line and with JSON's escapes in `E703`, and the two lines were written by different code.  The trial line and `E703` now write each argument as its literal, through the one renderer `vera verify`'s counterexamples use: `@Bool.0 = true`, `@String.0 = "q\"x\n"`.  A generated `String` argument is the string the solver chose: the compiled function was called with the solver's text of it, which spells an invisible character and one outside the Basic Multilingual Plane as an escape, so `requires(@String.0 == "\u{200B}")` failed as a precondition violation on its own generated input; one reader of a solver's string value now serves both the trial and its report.  **Breaking** for a consumer of `vera test --json`: each failure's `args` gives a `Bool` argument as a JSON boolean, `true` or `false`, where it gave the number `1` or `0`; a reader that compared the value with `1` compares it with `true`.  Every other argument's JSON value is unchanged.
