- The obligation table, the first half of Stage 27 (`vera/obligations/table.py`, #1695): one pass over the typed program lists every obligation site once as a row, and code generation emits a runtime check for every row the table holds guardable and for no other node, deciding no guard of its own (`WasmContext._record_check` takes the row; `EmittedCheck.row` names it; a check with no row is a compiler invariant). Every `vera verify` verdict is what it was. The compiled module changes where the table and the old decisions disagreed: a bare `put` into a refined `State` cell on the intrinsic route takes the cell's predicate guard beside the sign guard (it took the sign guard alone, so a non-positive value reached a `{ @Int | @Int.0 > 0 }` cell); a handler clause binder over an `Array`, `Map` or `Set` payload declared narrower than the payload is walked at run time, with the verifier still disclosing it until the second half; a later element of an array literal coerced to the literal's element type by the first element (`[@Nat.0, @Int.0]`) is guarded; a §2.6.5 guard on a value already of the refined type (a refined slot stored into a field of its own type, or bound by a `let` of its own type) is no longer emitted, since the slot's own binding is checked; the use of a guarded handler clause binder at a `@Nat` formal is no longer guarded a second time; and the `decreases` self-tail prefix is rendered only where a tail call splices it, so a function with no self tail call, or with a runtime postcondition, no longer carries its dead locals. `effect_bind` joins the obligation kinds: a `match` arm binder bound at a function type whose effect row is narrower than its field's (#1725), a row no runtime check can evaluate, listed by the table and disclosed by the second half.
