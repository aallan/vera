- **A source file that is not UTF-8 is refused with `E024`, at the file and its first byte that does not decode, by every command and for every module a program imports** ([#1666](https://github.com/aallan/vera/issues/1666)).  Every reading of a source was `read_text(encoding="utf-8")`, and the decoding error a file in another encoding raised reached no handler of its own: `vera check`, `vera verify` and `vera test` reported it as the internal error `E699`; `vera compile`, `vera run`, `vera ast`, `vera parse`, `vera fmt` and `vera serve` exited with a Python traceback, with nothing on stdout under `--json`; a source on stdin did the same; and an imported module that was not UTF-8 was `E013`, a module that failed to parse.  Every reading now goes through one reader, `vera.parser.read_source` (`decode_source` for the bytes `vera fmt` and stdin read), and a source that does not decode is `E024`, "Source file is not valid UTF-8": the byte and its offset, located at that byte's line and column in the file that holds it, with the `iconv` command that converts the file in its fix, and a UTF-16 or UTF-32 byte-order mark named.  Under `--json` it is in the command's envelope.  The language server reads a document's imports through the same resolver, so a module that is not UTF-8 is its `E024` there too, and `reconcile_file` (`scripts/check_reconciliation.py`) records it as the program's refusal where it raised.  A file that is UTF-8 reads as before: the 497 `.vera` files in the tree read the same through the old reader and the new.
