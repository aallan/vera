- The nightly mutation sweep no longer scores a function evaluated at import as survivors no test could kill ([#1740](https://github.com/aallan/vera/issues/1740)). mutmut forks a mutant's worker after the modules are imported, so a function that runs only at import never runs under its mutant. A rule over the sources (`at_import_units`, by `ast`) finds them at its conservative closure: a function is one only if every mention of it in `vera/` and `tests/` is a direct call by its plain name in code run while its module is imported (a module or class body, a default, the body of another such function, the import branch of a `__main__` guard). Any other mention makes it observable: an import of its name elsewhere (a re-export included), its name as a string, an attribute, a stored or passed name, a decorator, a call in the body of a method, a nested function or a lambda, in a generator expression past its leftmost iterable, or in an annotation under `from __future__ import annotations`. It names 27 in the tree, among them `vera/__init__.py`'s `_read_version`, `vera/ast.py`'s `_spelling` and `_stage`, and the four the nights scored as survivors: `monomorphize._builtin_return_tables`, `trap_registry._kinds` and `_emitters` in cycle 2, `fold._check_order` in cycle 3. Their sampled mutants are decided `at_import` without running: counted apart, outside the score's total and the survivor list, never planned; a window scored before the rule is decided again by it, and a window the rule decided reopens, before the night's results merge, once the rule no longer names its function.
