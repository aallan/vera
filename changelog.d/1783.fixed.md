- **A generic instantiated at a function type is compiled** ([#1783](https://github.com/aallan/vera/issues/1783)).  A call that passes a closure, or a value of a function type, for a generic's type parameter passed `vera check` and `vera verify`, and code generation refused the clone (`E600` at a parameter, `E601` at a return) and dropped every function that called it (`E620`), so `vera run` had nothing to run.  A clone spells its type arguments by name, and the width of a type expression was read from the name, which nothing answered for `fn(Int -> Int)`; it is now read from the typed program, where a function type is a closure pointer.  `idg(fn(@Int -> @Int) effects(pure) { @Int.0 * 2 })` for `forall<T> fn idg(@T -> @T)` returns the closure, and the prelude's `option_unwrap_or` at an `Option` of a function type, a function type at an `Array` element, a data type's field, a `Map` value, a `State` cell or an `Exn` payload inside a generic, and a generic `where` helper each compile and run.  No example, conformance program or documentation example changes verdict or emitted WebAssembly.
