- **A program generator, and three differentials over what it writes, nightly.** `tests/program_generator.py` writes a whole Vera program from a seed: up to three `data` declarations, up to six functions whose every slot reference is computed from the generator's own binding stack and whose contracts hold of every input their `requires` admits, and a `main` that prints each public function's value.  `tests/test_program_generator.py` holds each program to `vera check` with no diagnostic, `vera fmt`'s canonical form and a `vera verify` with no error and no timeout, and to three differentials: the module compiles with no E6xx diagnostic, exports exactly the public functions and runs each on the arguments the generator chose; `vera/reconcile.py`'s join reports no mismatch outside the classes `scripts/check_reconciliation.py`'s `KNOWN` names; and `vera test --distrust` reports no refuted proof, no trap it cannot attribute and no failing trial.  A find outside the known classes is minimised and recorded with its seed, the minimal program and what the generator expected of it.  `.github/workflows/nightly-generator.yml` runs 5,000 seeds a night at 14:17 UTC and files or updates one issue labelled `generator-find` when a night fails; every pull request runs ten pinned seeds, and a pull request that changes the generator runs 1,000.
  - Over the first 1,000 seeds (2,238 public functions, 2,114 of them tested and 2,056 proofs exercised in 28,529 trials), the known classes counted 1,516 mismatches of [#1695](https://github.com/aallan/vera/issues/1695)'s [#1629](https://github.com/aallan/vera/issues/1629) shapes in 707 programs, 792 of its [#1557](https://github.com/aallan/vera/issues/1557) shape in 480, 48 of [#1598](https://github.com/aallan/vera/issues/1598)'s in 40, and 3 verify refusals in 3 programs that [#1525](https://github.com/aallan/vera/issues/1525)'s checklist now names: a call whose argument constructs a data type its function names nowhere else loses the callee's postcondition.
  - The runs found one class of their own, [#1756](https://github.com/aallan/vera/issues/1756): an `if` or a `match` joining an `@Int` branch with a `@Nat` branch is typed `@Nat`, so binding it into a `@Nat` slot records no narrowing; `let @Nat = if @Bool.0 then { -1 } else { @Nat.0 };` passes `vera verify`, and the run's guard traps on it.  The generator counts it as a known class.
