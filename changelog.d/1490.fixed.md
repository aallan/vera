- **Every diagnostic carries a registered code** ([#1490](https://github.com/aallan/vera/issues/1490)).  Spec §0.5.1 requires a stable code on every diagnostic.  Five diagnostics about source code carried none, and neither did the command line's 25 JSON diagnostics, so `--json` had no `error_code` and the text no `[Exxx]` prefix, and nothing enforced one.
  - The missing-visibility error on a `fn` or `data` declaration is `E188`.  The removed alias `Float` is `E136`, the unknown type name it is.  Code generation's guard rail for a call with no target, module-qualified or bare, is `E624`.  The WAT assembler's failure is `E699`, as its sibling branch is.
  - The command line's diagnostics are `Diagnostic`s, in two ranges added for them.  `E8xx` is a program's own failure while it runs: `E800` is the runtime trap, located at the function that trapped, with its `trap_kind`, `frames` and `fix` kept.  `E9xx` is a refusal of the command line itself: `E900` a source file not found, `E901` an option a command does not take, `E902` options that contradict each other, `E903` a value an option does not take, `E904` a command line `vera` does not understand, `E905` a module that exports no function, `E906` a `--fn` that names no export, `E907` an entry code generation dropped, `E908` a program that lacks what its target needs, `E909` arguments that do not fit the function, `E910` an address `vera serve` cannot bind, and `E911` a missing optional dependency.  Each envelope keeps the fields it had and each description its text.  Each gains a rationale, a fix and spec §0.5.1, which states what the two ranges mean, and `vera errors` lists the codes under the phases `run` and `command`.  `vera ast --json` prints a file not found in its envelope.
  - `E607` is titled for what it reports: a `State` cell type that code generation cannot lower.
  - `scripts/check_diagnostic_fields.py` fails a diagnostic site with no code, which no opt-out waives.  It also fails a diagnostic built by hand (a dict with a `severity` key, or a string holding one), except at the two sites it names: `Diagnostic.to_dict` and the internal-error envelope's last resort.
