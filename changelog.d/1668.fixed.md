- **An array literal, an `if` and a `match` have the type all their parts give them, an open position included** ([#1668](https://github.com/aallan/vera/issues/1668)).  A part whose type leaves a position open, the `T` of a `None` or the element type of an empty literal `[]`, was held to the other parts with the position a wildcard, and the position stayed open in the type the whole was given.  So `second([None, Some("abc")])` passed `vera check` and `vera verify` into an `@Array<Option<Nat>>` parameter and `vera run` read the `"abc"` as a `@Nat`, `array_length([None, Some(1), Some("abc")])` checked, `let @Array<Array<Nat>> = [[], ["abc"]];` checked and failed to load, as did `first(if true then { ["abc"] } else { [] })` into an `@Array<Nat>` parameter, and `match @Nat.0 { 0 -> None, _ -> 5 }` and `if @Bool.0 then { None } else { Ok(1) }` checked.  The parts are now joined by one function, `CallsMixin._join`: the type of the first typed part, with each position it leaves open given by the first later part that fills it, and each open type variable bound by name, so that one occurring twice takes one type.  It does not fill a type variable where code generation compiles behaviour for it, inside a function type or under a data type's parameter that a constructor field holds a function over: code generation finds a generic call's instantiation from its arguments and the type it is expected at, not from a join.  Nor does it fill a built-in's variable that a parameter of the call mentions and the arguments left unbound, which stands for a type a failed substitution lost ([#1684](https://github.com/aallan/vera/issues/1684)); a built-in's variable that no parameter mentions, as `map_new()`'s `K` and `V`, is marked free at the call, an open position as a constructor's type parameter no field holds is, and filled.  The shapes the join leaves keep the verdict each site gave them, bar a `match` arm a variable withheld for behaviour would have to take the type of, which is now refused (`E302`) where the arm's type was taken without comparing the two.  An array literal has that element type, so `[None, Some(1)]` is an `Array<Option<Nat>>`, and an element that does not fit it is `E162`, which names the elements the type comes from (`the type of element 0, completed by element 1`).  An `if` whose branches no open position reconciles is `E301`, and such a `match` arm is `E302`, which now shows an open position as `?` and so is reported once where an arm is checked more than once.  Branches and arms that agree once their open positions are filled now check: `match @Nat.0 { 0 -> Ok(1), _ -> Err("e") }` was refused `E302` and is a `Result<Nat, String>`.  A position no part fills stays open for the context to fill, as before.  `tests/test_array_literal_open_position_1668.py` holds the class: 1,584 cells over the site, the type that leaves the position open, how deep it sits, what fills it and where the whole stands, each expectation stated by rule, 162 of them strict xfails for [#1684](https://github.com/aallan/vera/issues/1684): a `let` or a return refuses a type variable the parts leave open, which an argument fills; 48 cells over a variable that occurs twice, a built-in's fresh variable and each shape the join does not fill, at each site, and four programs refused at check that f3b4415d ran or trapped on.
