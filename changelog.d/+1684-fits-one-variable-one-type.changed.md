- **Breaking: a closure, or a data value holding one, from a generic call that leaves its type variable unfixed fits no parameter, array element or branch that gives the variable a type** ([#1684](https://github.com/aallan/vera/issues/1684)).  `use(mk(()))`, with `mk(@Unit -> @Endo<T>)` returning the identity and `use` taking a `fn(Int -> Int)`, passed `vera check` and trapped at run time; it is refused with `E202`, whose fix writes the closure at the type the parameter asks: `fn(@Int -> @Int) effects(pure) { ... }` in place of `mk(())`.  Giving the call an argument that fixes `T` keeps it.  A closure whose variable no argument fixes, passed where the parameter's own variable is unfixed too, is refused the same way, which `vera run` ran.  No example, conformance program or documentation example is affected.
