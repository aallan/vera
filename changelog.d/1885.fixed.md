- **Breaking: a function value whose parameter is narrower than the function type it reaches is refused at check** ([#1885](https://github.com/aallan/vera/issues/1885)).  A `fn(@Pos -> @Int)` or a `fn(@Nat -> @Int)` closure was accepted where a `fn(Int -> Int)` was expected, by a `let`, an argument, a constructor field, an `if` or `match` join, a return, an array or tuple element, a handler's state, a generic instance chosen from another argument (`array_map` over an `Array<Int>`), or, inside a generic function, an argument or a destructured component whose function type holds the function's type variable, and nothing was recorded at the flow: the `Pos` closure trapped at its own entry on a value the function type admits, and the `Nat` closure bound -5 to its `@Nat` parameter with no check at all.  Such a value is now refused with E190 (spec §2.8): the narrowing the checker permits for a value does not reach a function type's parameter, which holds no value to check.  Two refinements of one base fit there only where they state the same predicate: whether one implies the other is the verifier's to decide, of a value, and a function type's positions hold none.  So a `fn(@Pos -> @Int)` at `fn(Big -> Int)` is refused too, though `Big` implies `Pos`.  Declare the closure's parameter at the type the position gives it and narrow inside (`fn(@Int -> @Int) effects(pure) { let @Pos = @Int.0; ... }`), or give the position the narrower type (`array_map` over an `Array<Pos>`).
