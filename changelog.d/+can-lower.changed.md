- **A construct code generation cannot lower is refused at check, where it is written** ([#1597](https://github.com/aallan/vera/issues/1597), [#1512](https://github.com/aallan/vera/issues/1512), [#1506](https://github.com/aallan/vera/issues/1506), [#1499](https://github.com/aallan/vera/issues/1499), [#1522](https://github.com/aallan/vera/issues/1522)).  Each passed `vera check` and `vera verify`, and was then dropped at compile (E602, E607, E612, E613) or compiled to a module that failed to load.
  - A handler for any effect but `State<T>` and `Exn<E>`, a host effect's (`handle[Http]` as a mock) or a user-declared one's ([#1597](https://github.com/aallan/vera/issues/1597)): E340 at the handler.
  - A `State` cell whose value is a `(ptr, len)` pair (`String`, `Array<T>`, a refinement or alias of either) or has no representation (`Unit`), in a handler or a declared row, an `Exn` payload with no representation, and an inline refinement as a handler's cell type ([#1512](https://github.com/aallan/vera/issues/1512)): E340 at the type.  The fix for a pair cell is a one-constructor `data` wrapper, `private data Text { T(String) }` and `State<Text>`.
  - A `State` clause whose body does not end in exactly one `resume(...)`, or whose `with` update holds one: E340 at the clause, whether an operation reaches it or not.
  - A quantifier predicate whose parameter or result is a type parameter, and a bound typed by one ([#1506](https://github.com/aallan/vera/issues/1506)): E179 and E128 at the generic, for every instantiation.  A type parameter as the index type is still accepted, since it lowers at every instantiation.
  - A call to a user-declared ability's operation, a `where` constraint naming a user-declared ability, and a qualified ability call such as `Eq.eq(1, 1)` ([#1499](https://github.com/aallan/vera/issues/1499)): E340.  The qualified call was E220, whose fix said to declare an effect named `Eq`; its fix is the bare call now.  A qualified call to an operation the ability does not declare, `Eq.nope(1)`, stays E220, whose message now names the ability and the missing operation, and whose fix declares a function under its own name.
  - A clause-body `State` operation that a type-parameter cell can shadow ([#1522](https://github.com/aallan/vera/issues/1522)): E339 at the generic, conservatively, so `g(true)`, which ran, is refused with `g(5)`, which was dropped.
  - Code generation's refusal sites for these rules are internal errors (E699), which no checked program reaches.  E607 and E612 stay user-facing for a `State<T>` or `Exn<T>` clone instantiated at a type the rule refuses, which the checker cannot see without the instantiation set ([#1679](https://github.com/aallan/vera/issues/1679)).
  - DESIGN.md's effects sentence, FAQ.md, SKILL.md, EXAMPLES.md and spec §6.3.3, §7.3.3, §7.5, §8.9.3, §9.8 and §11 state what is implemented.
