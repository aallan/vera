- **The mutation lanes run pytest with `-p no:faulthandler`, so wasmtime's trap handlers survive mutmut's second in-process session** ([#1747](https://github.com/aallan/vera/issues/1747)).  pytest's faulthandler plugin records the process's signal handlers when a session starts and restores them when it ends; wasmtime installs its trap handlers once per process, at the first `Engine`.  mutmut's fork runner runs the stats pass and the clean pass as two sessions in one process, so the first session's end put the pre-session handlers back over wasmtime's, and the clean pass died on its first WebAssembly trap (SIGILL, exit -4) on each of the nightly sweep's first two nights ([#1745](https://github.com/aallan/vera/issues/1745)), every forked mutant run inheriting the loss.  With the plugin out nothing restores the handlers.  `tests/test_wasmtime_traps_across_pytest_sessions_1747.py` runs two sessions over a trapping module in a subprocess, with and without the plugin, on Linux, where traps are signals; and a slice record's engine tail now starts a row at a fault dump's first line wherever mutmut's spinner left it, so the record names the dying test.
