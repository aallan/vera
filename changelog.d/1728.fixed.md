- **A `\u{...}` escape that names a surrogate, `\u{D800}` to `\u{DFFF}`, is refused with `E009` where escapes are decoded** ([#1728](https://github.com/aallan/vera/issues/1728)).  The escape decoder refused only a code point above U+10FFFF, so a lone surrogate, which is no Unicode scalar value and has no UTF-8 encoding, passed `vera check` and `vera verify`, and `vera compile`, `vera run` and `vera serve` exited with a Python `UnicodeEncodeError` traceback from the string pool.  Every string literal is decoded at one place, so the refusal holds in an expression, a `match` pattern, an interpolated string's text, a contract, a refinement and an imported module (there as the module's `E013`); its fix writes a character outside the Basic Multilingual Plane as one escape of its code point, `\u{1F600}`, never the UTF-16 pair `\u{D83D}\u{DE00}`.  Spec §1.6's escape table names the domain, a Unicode scalar value.  A raw surrogate cannot enter from a file: its UTF-8 form does not decode, which is `E024`.
