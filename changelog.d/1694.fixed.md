- **Every name is resolved once, by the resolver pass** ([#1694](https://github.com/aallan/vera/issues/1694)).  `vera.binding` gives every declaration of the entry file, each module and the prelude an identity and binds every call, data type, type alias and constructor name to one declaration, before any later stage asks; the checker resolves its calls, types and constructors by reading the binding, and code generation and the verifier compile and verify the linked program, every declaration under its link name, so no two stages read one name two ways.  Each instance of the class:
  - Two same-named functions no namespace can name together compile and run: a selective import beside the other module's own `f`, a module declaring `f` over the `f` of a module it imports, and two modules' private helpers of one name were refused at compile with `E608` ([#1498](https://github.com/aallan/vera/issues/1498)).
  - A module generic called from another file at that file's own `data Shape`, where the module declares `type Shape = Int;`, compiled to a module that failed to load ([#1519](https://github.com/aallan/vera/issues/1519)).
  - `show()` and `hash()` of a value whose type an imported signature names read the name through the importing file's type aliases, so an entry-file alias spelled like the imported type printed a wrong result ([#1548](https://github.com/aallan/vera/issues/1548)).
  - A module generic's call to its own `where` helper compiled, in an importer, as a call to the module's same-named top-level generic, so an `ensures` proved for the helper failed at run time ([#1581](https://github.com/aallan/vera/issues/1581)).
  - A user function's `E602` is kept whatever its line: it was suppressed when its line fell inside a compiled prelude generic's line span, and the function was dropped with no diagnostic ([#1549](https://github.com/aallan/vera/issues/1549)).  Code generation now asks whether the diagnostic is about a compiled template's declaration.
  - A type alias resolves an alias declared after it in its namespace, as a data type resolves wherever it is declared; inside a cycle of mentions, source order still holds and a cycle is `E132`.  An alias naming a later one was registered unresolved and every use of it refused with `E140` or `E202` at the use ([#1552](https://github.com/aallan/vera/issues/1552)), in a type argument, a constructor field, a function signature, and an effect's or an ability's operation signature alike, and the verifier's own registration reads the same rule.
  - Refinements in a type argument are two slot names when their predicates differ: a slot name's argument keeps its predicate, canonically, so `@Array<{ @Int | @Int.0 > 0 }>` and `@Array<{ @Int | @Int.0 < 0 }>` are two stacks and a reference's predicate is compared with its binding's ([#1674](https://github.com/aallan/vera/issues/1674)); every parser of slot-name text reads such an argument as one.
  - The verifier verifies the program code generation compiles: a callee is the declaration its call is bound to, so two `where` helpers of one name under one top-level function are two functions for the disclosure rule, and the caller of the one whose result is established proves at Tier 1 where it was demoted (`tier3`, `E534`).
  - A refinement predicate a module's type writes is read as the module binds its names wherever a value is checked against the type, in another file too: a module alias `type Pos = { @Int | pos(@Int.0) };` checked at a call from a file that declares its own `pos` was proved with that file's `pos`, a Tier 1 the run's guard refuted, and is now reported as violated (`E505`) where the run traps.
  - The instances the reserved prelude names answer (Changed, [#1469](https://github.com/aallan/vera/issues/1469)) are [#1495](https://github.com/aallan/vera/issues/1495), [#1496](https://github.com/aallan/vera/issues/1496), [#1553](https://github.com/aallan/vera/issues/1553), [#1556](https://github.com/aallan/vera/issues/1556), [#1560](https://github.com/aallan/vera/issues/1560) and [#1600](https://github.com/aallan/vera/issues/1600), and the one a declaration's own WebAssembly namespace answers (Changed) is [#1494](https://github.com/aallan/vera/issues/1494).
