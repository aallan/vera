- **A check on a tail call's result runs** ([#1849](https://github.com/aallan/vera/issues/1849)).  A function whose last expression is a call returning the `Int` form of its own composite return type (`wrap(@Int.0)` returning `@Option<Int>` into an `@Option<Nat>`, through an `if` or `match` arm, a block's tail, a `where` helper, a generic callee or a call by the module's own path) compiled the call as a `return_call` with the coercion's check after it, so the check never ran: `Some(-1)` reached the `@Nat` binder of the caller's `match`, while `vera verify` reported the narrowing as a runtime check and reconciliation found it in the module.  Whether a call leaves by `return_call` is now one rule read from the obligation table: a call in tail position after which no check runs, none standing at the call and none after the function's body, so the call lowers to a plain `call` and the check traps; the same value bound by a `let` first already trapped.  Every other tail call keeps its `return_call`, the compiled output of the 252 example and conformance programs that compile and of the program generator's 1,000 seeds is unchanged, and a code generation that would leave a check after a `return_call` stops with an `E699` naming the function.
