- An operation on a value of a zero-size type (`Unit`, a `Future<Unit>`, a refinement of `Unit`) has its meaning at run time ([#1870](https://github.com/aallan/vera/issues/1870)).  `() == ()` is `true` and `!=` is `false`, in a body, a `requires`, an `ensures`, an `assert` or an argument.  `vera check` and `vera verify` accepted these and `vera compile` wrote the module, which failed to load (`type mismatch`) for every function in the file.  `show` and `hash` of one evaluate it (`show(IO.print("a"))` printed `unit` without printing `a`), and a `match` on one takes its first arm (code generation dropped the function, `E602`).  Operands are evaluated in order for their effects, so `IO.print("a") == IO.print("b")` prints `ab`.  The verifier proves an equality of two such values at Tier 1, and refutes a claim that they differ.  It had refuted a true `requires(mk(1) == mk(1))` over a function returning a refinement of `Unit` (`E501`).
- A prelude generic that reads its type parameter (`option_unwrap_or`, `option_map`, `option_and_then`, `result_unwrap_or`, `result_map`), and `array_fold`'s accumulator, instantiated at a zero-size type is refused at `vera check` (`E206`), as a user generic is ([#1870](https://github.com/aallan/vera/issues/1870)).  `option_unwrap_or(Some(()), ())` passed `vera check` and stopped `vera verify` with an internal error in the prelude (`E699`).  `array_fold` at a `Unit` accumulator wrote a module that did not load.
- A postcondition's reference to a zero-size result (`@Unit.result`) is refused at `vera check` (`E182`), as a read of a `@Unit` slot is ([#1870](https://github.com/aallan/vera/issues/1870)).  `ensures(@Unit.result == ())` passed `vera check` and stopped `vera verify` with an internal error (`E699`).  Upgrade: a postcondition about a `Unit` result says nothing, since the result has one value; write `ensures(true)`.
- An expression of type `Never` whose code did not end in an instruction that stops control (an `if` or a `match` whose arms all throw, a `handle` whose body and clause throw) is followed by `unreachable` wherever it stands ([#1870](https://github.com/aallan/vera/issues/1870)).  As a call argument, an array element, an index, a `let` value, an `if` condition, the right operand of `&&`, `||` or `==>`, or a handler's value, it wrote a module that failed to load (`type mismatch`), behind a green `vera check` and `vera verify`.  A `Never` part of a string interpolation dropped its function (`E615`), and so did a `match` on a `Never` scrutinee (`E602`); both run.
