- **A `match` is judged and verified to the full depth of every pattern** ([#1697](https://github.com/aallan/vera/issues/1697)).  The exhaustiveness check covered a data type by the constructors its arms name at the top, so `match W(Green) { W(Red) -> 1 }` over `data Wrap { W(Colour) }` checked clean and ran the `W(Red)` arm, `match Some(Green) { Some(Red) -> 1, None -> 0 }` printed 0 ([#1540](https://github.com/aallan/vera/issues/1540)), and a tuple was not judged at all, so `Tuple(Some(@Int), @Int) -> @Int.0` alone returned 3 for `Tuple(None, 3)`.  The verifier took an arm to be taken whenever its outer constructor matched, so after `Some(None) -> 0` the arm `Some(Some(@Int)) -> @Int.0` was unreachable to the proof and `ensures(@Int.result == 0 || @Int.result == 1)` was proved over a function that returns 7 for `Some(Some(7))` ([#1562](https://github.com/aallan/vera/issues/1562)).  One module, `vera/patterns.py`, now reads a pattern to its full depth for both.  The check reports `E311` whenever a value of the scrutinee's type matches no arm, naming the cases missing at the first position that leaves one: a constructor missing at the top by its name, as before, and a case inside a constructor as a pattern, `W(Green)`, `Some(_)`, `Tuple(None, _)`.  A field whose type is a type parameter the function declares is covered only by a wildcard or a binder there, as a `match` over a `T` needs a catch-all (`E313`), since `T` may be `Int`: `Some(None) -> 1, Some(Some(_)) -> 2, None -> 0` over `Option<T>` checked clean and returned 0 for `Some(5)`, and is now `E311` naming `Some(_)`.  The verifier's condition for an arm is every test its pattern makes, each on the field its path reaches, so the `ensures` of [#1562](https://github.com/aallan/vera/issues/1562) is refuted (`E500`), a guarded refined binder under a nested pattern carries its predicate in its arm, and an arm after a nested one is reached by exactly the values the earlier arm does not take.  No pattern condition models a `String` literal, so a `match` with a `String` literal inside a constructor in an earlier arm is not translated and its `ensures` is Tier 3 (`E522`), where `ensures(@Int.result != 2)` over `Ok(_) -> 0, Err("a") -> 1, Err(_) -> 2` was proved.
