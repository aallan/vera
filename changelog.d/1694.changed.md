- **A program's declarations and the compiler's own functions and exports are two namespaces** ([#1694](https://github.com/aallan/vera/issues/1694)).  Every declaration's WebAssembly function is named `$:` followed by its link name (`$:main`, `$:mod$util$helper` for `helper` in `module util;`, `$:f$where$h` for a `where` helper, `$:identity$Int` for a clone), and no function the compiler writes for itself (`$alloc`, `$gc_collect`, a lifted closure's `$anon_0`, a derived `$eq_Shape`) has a `:` in its name, so a user function named `alloc`, `gc_collect`, `anon_0` or `eq_String` beside a program that makes the compiler emit its own no longer fails to compile with a duplicate identifier ([#1494](https://github.com/aallan/vera/issues/1494)), and under `--target wasi-p2` a function named `wasi_tbl`, `wasi_arena_ptr` or `cabi_realloc` compiles instead of being refused as a reserved identifier.  **Breaking**: the compiled module exports its runtime under names that start with `vera.`, which no Vera identifier can spell: its linear memory as `vera.memory`, the allocator as `vera.alloc`, the GC globals as `vera.heap_ptr`, `vera.gc_sp` and `vera.gc_stack_limit`, and the wrapper registration as `vera.register_wrapper` (and the WASI 0.2 core module's adapter table, arena pointer and realloc as `vera.wasi_tbl`, `vera.wasi_arena_ptr` and `vera.cabi_realloc`), so a public function named `alloc` is exported as `alloc` beside the allocator.  To upgrade, an embedder that read `memory`, `alloc`, `heap_ptr`, `gc_sp`, `gc_stack_limit` or `register_wrapper` from a compiled module's exports reads the `vera.`-prefixed name (`instance.exports["vera.memory"]`); a program's own exports keep their names.  The `vera compile --wat` text and a backtrace `wasmtime` prints itself name a declaration's function with its `:` (`Main!:handle`); Vera's own trap reports name it as declared.
