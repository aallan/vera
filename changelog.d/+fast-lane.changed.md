- **A pull request's CI runs the suite in Python 3.12 shards on Linux and Windows, and the full OS × Python matrix runs where the version rises and every night.**  The pull-request lane is lint, typecheck, three Linux and two Windows shards of the suite (`pytest -n 4 --shard=K/N`: `tests/shard.py` puts a test in the shard its node id hashes to, after `-k`, `-m` and the class-instrument sample, so the shards are the suite between them and no durations file needs keeping), eager-GC, browser parity, and the security and supply-chain jobs.  The 13-cell matrix runs on a pull request that raises `[project].version` (the `plan` job now answers that for a pull request's head against its base), on the push event its merge produces, and nightly, and its cells are no longer required checks: the new `matrix-gate` job (`scripts/matrix_gate.py`) is, passing when the plan succeeded and the matrix either passed or was skipped because the version stays.  The Linux aarch64 cell stays advisory (`continue-on-error`): its failure fails neither `matrix-gate` nor the run, and files no issue.  Any other failed cell on a push or nightly run files one issue per workflow and branch, labelled `bug` and `ci`, or comments on it when it is open (`matrix-issue`).  `release.yml`'s first job waits, for at most 100 minutes, for CI's run on the commit a release publishes, and the release goes on only once that run has succeeded (`scripts/await_ci.py`).  Each push run on `main` has a concurrency group of its own, its commit, so no push run waits behind another or is dropped while it waits, and every commit keeps a completed run.  Every CI job carries an explicit `name:`, which is its check's name.  `tests/test_gate_placement.py` keeps the property that every gate the hook runs also runs in CI, now on five events with the shards reassembled into the suite, and drops its pins of the CI layout and its list of evasions.
