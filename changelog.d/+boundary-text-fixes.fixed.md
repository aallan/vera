- A source file that starts with a UTF-8 byte-order mark is read as the file without it, by every command and for an imported module, where it was refused with `E006` at line 1, column 1 ([#1790](https://github.com/aallan/vera/issues/1790)).  `vera fmt --check` reports a marked file as not canonical and `vera fmt --write` writes it without the mark.  `E006` also names a character that has no glyph (a control or format character such as a zero-width space) by its code point and name, `U+200B (zero width space)`, where it quoted the invisible character itself.
- The quoted `String` in an uncaught exception's message is cut at a character boundary ([#1526](https://github.com/aallan/vera/issues/1526)).  A thrown `String` longer than 64 bytes whose cut fell inside a multi-byte character ended its quoted value in U+FFFD; the quoted value is now whole characters, on `vera run`, `--target wasi-p2` and the browser runtime.  The provider error text `std.inference` quotes from an HTTP error body longer than its 64 KiB read cap is cut the same way.
