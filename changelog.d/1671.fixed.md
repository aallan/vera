- **A `match` whose scrutinee is already an error is not also reported non-exhaustive** ([#1671](https://github.com/aallan/vera/issues/1671)).  The checker types an expression it has refused as unknown, and the exhaustiveness check judged an unknown scrutinee as a type with an infinite domain, so `match @Option<Int>.0 { Some(@Int) -> @Int.0, None -> 0 }` with no `Option<Int>` binding in scope was reported `E130` at the reference and then `E313` at the `match`, whose arms cover both of `Option`'s constructors.  Every scrutinee the check types unknown after an error drew the same `E313`: an undefined call (`E200`), a result reference naming another type (`E163`) or written outside a postcondition (`E131`), an undefined constructor (`E210`), an index into a value that is no collection (`E161`), the slot inside a block or in both branches of an `if`, a `let` declaring the removed alias `Float` (an error with no code), a constructor of a declaration refused as `E158`, and a call two imports supply (`E155`), the last two with their error placed at the declaration or the import.  A scrutinee typed unknown, a refinement of one included, once the check has reported an error is now not judged for coverage (spec §4.9.2).  Its arms are still checked, so an error inside one is still reported, and an arm after a catch-all is still reported (`E310`), since that reads the arms alone; the pattern-fit rule (`E314`) already withheld itself from an unknown scrutinee.  Every error the module has reported by the time the scrutinee is typed counts, because the error behind it can sit at a declaration or an import.  A scrutinee typed unknown with no error reported, an `apply_fn` over a type variable in a `forall` body, is judged as before: its `E313` is the one error that refuses the program, which without it passes check and verify and has its functions dropped by code generation (`E620`).  `tests/test_match_unknown_scrutinee_1671.py` holds the class: 297 cells over ten ways a scrutinee comes to be in error, eleven arm shapes and three positions (a function body, an `ensures`, a `where` helper), each reporting exactly the scrutinee's own codes and then what its arms report whatever the scrutinee, 216 of them red at a5b5de8f by one trailing `E313`; 197 cells over the same arms over the scrutinee written correctly, each keeping its verdict (`E310`, `E311`, `E312`, `E313` or `E314`) and, where the arms draw none, verifying with every obligation proved; 99 over a scrutinee whose error leaves it a type (a call with the wrong arity, a `let` whose initialiser is in error, an `if` with one branch in error), and 11 over an unknown scrutinee with no error reported, each judged as before.  The six cells of `tests/test_result_reference_type_1517.py` that expected `E313` after a refused result reference now expect `E163` alone.  The `examples/` and `tests/conformance/` programs and the documentation blocks pass their gates as before.
