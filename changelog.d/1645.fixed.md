- **Forty-two run-level conformance programs run what their headers name** ([#1645](https://github.com/aallan/vera/issues/1645)).  Each program's `main` reaches every function the program defines and calls every built-in its manifest `features` names, and prints, for each case, the value it computed, which the entry's `expected_stdout` pins.  Eight programs had no `main`, so `vera run` executed their first public function alone; four had a `main` that called none of their tests or whose check could not fail; eighteen ran one case of several; three named in their header a feature the file did not contain (`ch01_string_escapes` now prints the `\r`, `\0` and `\u{XXXX}` escapes, `ch04_string_interpolation` interpolates a `Float64`, and `ch07_exn_param_alias` throws and catches across alias depths); and nine had a check too weak to see a wrong value, such as `ch05_capture_array_index`, whose first case passed under an identity map and its second under a transpose, and which now prints each whole result.  `tests/test_conformance_run_reach.py` holds the 42 to the first two rules: 86 cells, 46 of them red before the change.  The distrust corpus (`tests/test_distrust_corpus.py`) runs 155 proved functions in 79 programs, where it ran 167 in 84: twelve of the old `main`s were pure functions the verifier proved, and their replacements print, under contracts `vera test` skips as trivial.
