- **The hosts bind a module's imports from the built-in registry, and spec §9's signature tables are rendered from it** ([#735](https://github.com/aallan/vera/issues/735)).  The Python host binds exactly the `vera` imports a module declares, each through the binder of its registry row's family (`HOST_BINDERS` in `vera/codegen/api.py`), and refuses an import no row declares, or one no binder defines, with a `HostBindingError` naming the row; `CompileResult` no longer carries the thirteen per-family `*_ops_used` sets, and code generation records the host imports a module uses in one set where it kept thirteen.  The browser runtime holds every import to a roster of the registry's 83 rows, which `scripts/render_lists.py` renders into `vera/browser/runtime.mjs`, and refuses one no row declares or the runtime does not bind.  Each row names the WASI worlds whose component implements it, and the WASI target's refusal lists are derived from them; a refusal lists the imports the module declares, its families in the registry's order.  The Signature cells of spec §9's sixteen signature tables are rendered from the records and the effects' operations in one notation, which moves 40 cells' notation and no type, and `vera/monomorphize.py`'s two built-in return tables are read from the records.  Compiled WAT is identical to the base's over the corpus.
