- **A pull request that changes only the VS Code extension's own files runs plan, lint, security and matrix-gate, and the other jobs stand down** (`scripts/ci_changes.py`).  The plan job asks whether every file the pull request changes from its merge base, a rename's old name included, is under `editors/vscode/` and is the extension's code, manifests, lockfile or icon, which `vscode-extension.yml` builds and tests; the extension's grammar, which `scripts/render_lists.py` renders, and its README and CHANGELOG, which the documentation gate's coverage rule reads, are not.  On `inert=true`, typecheck, eager-gc, browser-parity, wheel-preflight, dependency-audit, package-distribution and sbom are skipped by their `if:`, which reports success under each job's name, and the five shard cells skip their steps, since a matrix job skipped whole reports one check under its unexpanded name; every required check keeps its name.  Of the 120 pull requests merged from 2 September to 21 October 2026, 6 changed only `editors/vscode/package.json` and `package-lock.json`, Dependabot's npm updates; no other change stands a job down, because the suite reads the documents and the workflows.  `tests/test_ci_changes.py` reads the workflow as data: every required check reports on every pull-request event, the filtered jobs stand down on an inert pull request and run every step on any other, and a missing answer runs every job.
- **The coverage job's floor is 94%** (`--cov-fail-under=94`, where it was 80).
- **The CHANGELOG gate diffs against the pull request's base branch.**  `scripts/check_changelog_updated.py` takes the base as its argument, and lint passes `origin/<github.base_ref>`, where the gate read `origin/main` whatever the base was, so a fragment an integration branch already carried satisfied every pull request into it.  A base the argument names that git cannot find exits 2.
- **Lint no longer repeats the suite's work.**  It ran `scripts/check_examples.py`, `scripts/check_doc_examples.py` and `scripts/check_examples_run.py`, whose work the suite does: the examples' check and verify (`tests/test_verifier_contracts.py`, and `tests/test_pipeline.py`, which holds each stage to its command); every gated document's Vera blocks and the coverage rule (`tests/test_check_doc_examples.py`), now with the `vera run examples/...` invocations each document names, which no test ran; and the examples' runs, in `tests/test_check_examples_run.py`'s new `TestRealExamples`, the 36 examples `RUN_SPECS` names run in process and read by the gate's two signals.  The scripts stay for local use, and `tests/test_gate_placement.py` matches the doc-example hook with a run of the whole suite.
- **The eager-GC lane is one pytest run**, `pytest tests/test_conformance.py tests/test_check_examples_run.py::TestRealExamples -k run -n auto` under `VERA_EAGER_GC=1`, where the examples ran through the script.
- **Every context value in `ci.yml` reaches a shell through `env:`.**  Four run commands wrote one into their text: the shards' `--shard`, the test matrix's `--matrix`, the release-mode check's base and the JavaScript coverage report's directory.  `tests/test_gate_placement.py` reads a step's `env:` into its command.
- **The `mutation (diff)` check is red for a defect and green for an unfinished run** (`scripts/mutate_diff.py`).  It exits 1 on a survivor, whatever stopped the run; 2 when the engine fails, mutmut reports a mutant of a function the lane did not map, or the lane itself fails; and 0 otherwise, where it exited 2 for every run its budget stopped: on [#1753](https://github.com/aallan/vera/pull/1753)'s final head the run took 2,410 s against its 2,400 s budget, and of 576 mutants killed 209, timed out 6 and left 361 not checked, none surviving, and the check was red.  A run that its budget stops, or that leaves a mutant undecided (`not checked`, `suspicious`, `segfault`, interrupted), passes when no mutant survived, with the headline `Incomplete: ...` in the job summary and a `::warning::` annotation on the pull request.  No other step of the workflow reads the exit status.
