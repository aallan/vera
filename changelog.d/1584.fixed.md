- **Every element of an array literal is held to the literal's element type** ([#1584](https://github.com/aallan/vera/issues/1584)).  The checker took an array literal's element type from its first typed element and never compared the other elements with it, so `array_length(["a", 5])` passed `vera check` and code generation wrote a module that failed to load, and `[@T.0, 0]` passed in a `forall<T>` body, where `T` is rigid, and failed to load once instantiated at `String`.  Each element after the first typed one is now held to the element type by the judgement a call argument is held to its parameter by, one method the two share (`_fits`): a subtype, or a type that a type variable still unresolved on either side leaves compatible, so `[None, Some(1)]` checks as before.  An element it refuses is the new `E162`, reported at the element and naming its position, its type and the element type.  The element type is still the first typed element's, a literal's type is unchanged wherever every element fits, and a zero-size element type is still refused once for the whole literal (`E135`).  `tests/test_array_literal_elements_1584.py` holds the class: 183 cells over where the element is, what it is and fifteen positions the literal stands in, 400 pairs of element types against an oracle of their own, and 41 literals that check with the type they had.  The `examples/` and `tests/conformance/` programs check exactly as before, and the new negative fixture `ch04_array_literal_element_type` is refused with `E162`.
  - An array literal whose first element leaves a type position open, a `None`'s `T` or an empty literal's element, keeps that position open and accepts elements that fill it with different types; it is filed as [#1668](https://github.com/aallan/vera/issues/1668).
