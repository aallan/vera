- **The nightly full matrix is a workflow of its own, and every job runs on a pinned image** (`.github/workflows/nightly-matrix.yml`).  The nightly run was a schedule of `ci.yml`'s own, so each night's completion started a run of `release.yml` whose gate skipped every job (run 40857508689 on 2026-10-29).  Nightly matrix calls `ci.yml` with `nightly: true` on the same cron and on demand, and a called workflow's jobs run inside its caller's run, so the release hears CI's push and pull-request runs alone and the matrix keeps one definition.  Every `runs-on` names an explicit image: `ubuntu-latest` gives way to `ubuntu-24.04`, and `windows-latest` to `windows-2025-vs2026`, the Windows Server 2025 image that label and `windows-2025` name since June 2026, so the five required shard checks are named `test (ubuntu-24.04, 3.12, shard K/3)` and `test (windows-2025-vs2026, 3.12, shard K/2)`.  The nightly run also watches the floating `ubuntu-latest`, `windows-latest` and `macos-latest` labels and Ubuntu 26.04 under Python 3.12 (the `watch` job): advisory cells whose failure files an issue and blocks nothing, and the issue names the image each failed cell ran on (`ImageOS`, `ImageVersion`).
