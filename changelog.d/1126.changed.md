- **The lock moves to z3-solver 5.3.2.0, and the hold on z3-solver 5.x that began on 2026-07-21 ends** ([#1126](https://github.com/aallan/vera/issues/1126)).  `uv.lock` moves from 4.16.0.0 to 5.3.2.0 and nothing else in it moves.  The per-obligation differential over the 323 `.vera` files under `examples/` and `tests/conformance/` is identical on the two solvers: the same 3,095 obligations, each with the same kind, status, line, column, code and description.  CI's jobs and an installed `veralang` resolve the unbounded `z3-solver>=4.15.5`, and have run 5.x since 5.0.0.0 was published on 2026-07-17; the lock governed `uv sync` environments alone.  The floor is unchanged, and the comment above it in `pyproject.toml` now records that the 5.x wheels are tagged `macosx_13_0_arm64` again, where 4.15.5 through 4.16.0 were tagged `macosx_15_0_arm64`, so README §Supported platforms, not the floor, states the macOS baseline.  That section now says what an install does on the platforms it leaves out of scope: on macOS 13 and 14 every dependency resolves to a wheel, and both stay unsupported and untested; where no z3-solver wheel matches, `pip install -e .` builds z3-solver from source, and `--only-binary :all:` stops at a "no matching distribution" error.  `.github/dependabot.yml` no longer ignores z3-solver's major updates.
