- A refuted contract's counterexample lists the function's inputs, each written as the program would write it ([#1871](https://github.com/aallan/vera/issues/1871)).  It listed every constant the solver context had declared, the context's own among them (a call's stand-in `_call_take_14_3`, an array literal's `_lit_7_16`), a `@Unit` parameter as `@Unit.0 = 0`, and printed `Counterexample:` with nothing under it in a function with no parameters; each value was the solver's text of it (`True`, `1.600000000000000088817841970012523233890533447265625*(2**-4)` for `0.1`, a `String` with a raw newline, an array's carrier constant `Array_Int!val!0`).  The counterexample now lists each parameter by its slot reference, and `@T.result` for an `ensures`, each value the literal the canonical formatter writes: `true`, `0.1`, `"q\"x\n"`, `Some(7)`, `Tuple(7, true)`, `[4, -5]`.  A `Float64` is the shortest decimal that reads back as the same value, and NaN and the infinities are `nan()`, `infinity()` and `0.0 - infinity()`.  An array longer than eight elements shows its first eight and how many more there are (`[0, 1, 2, 3, 4, 5, 6, 7, ... and 2 more]`); an input whose value has no literal form (a `Map`, a `Set`, a function) is named with `its value has no literal form`; a zero-size input is not listed, and with nothing to list there is no header.  All ten diagnostics that carry a counterexample (`E500`, `E501`, `E502`, `E503`, `E505` twice, `E507`, `E526`, `E527`, `E528`) write it through one function, and the fix a diagnostic offers is computed from the model's values rather than from the text.
