- **A result reference is held to the function's return type** ([#1517](https://github.com/aallan/vera/issues/1517)).  The checker resolved a result reference's type arguments and then typed the reference as the return type whatever its head named, so on a function returning `@Int`, `ensures(@Qzt.result == 1)`, `ensures(@Nat.result == 1)` and `ensures(@String.result == 1)` each passed `vera check` and was proved at Tier 1, and on a function returning `@Bool` an `@Int.result` reached code generation, which wrote a module that does not validate.  A result reference now names the result only where its name is the return type's, judged as a slot reference is matched to its binding (spec §3.6, §3.8): the reference's name and the name a binding of the declared return type is bound under come from one renderer and are compared, so an alias at the head stays opaque (`@Cnt.result` for a `@Cnt` return, never `@Int.result`), type arguments resolve through aliases (`@Option<Cnt>.result` and `@Option<Int>.result` both name an `Option<Int>` result), a refinement written out is named by its base, and a function type written out is `@Fn.result`.  A reference of any other type is the new `E163`, reported at the reference: its message quotes the reference as written and the return type as the signature spells it, and its fix names the reference in that spelling, which the program accepts in place of the refused one; the reference then types as unknown, as an unresolved slot reference does.  A return type the check refuses where it is written is not judged, so its own error stands alone, as before.  `tests/test_result_reference_type_1517.py` holds the class: 135 cells over where the function is declared (at the top level, as a `where` helper, in an imported module), fifteen return types and fourteen ways a reference's type can differ from the return type, each of which also checks the program clean with the fix's reference written in, and 69 cells of references that name the result, chapter 3's examples among them, which check clean and whose postconditions verify as they did.  Every `examples/` program, conformance program and documentation block still passes its gate, and the new negative fixture `ch03_result_reference_type` is refused with `E163`.
