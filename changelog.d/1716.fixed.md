- **An `if`, a `match` or an `Exn` handler has the type its arms share** ([#1716](https://github.com/aallan/vera/issues/1716)).  The checker recorded a join at one arm's type, keeping that arm's refinements whatever the other arms stated, so `if @Bool.0 then { @Int.0 } else { @PosInt.0 }` was a `@PosInt` and the same `if` with its branches swapped an `@Int`.  A join is now recorded at what every arm that completes states, position by position and in either order: a refinement one arm lacks, or states with another predicate, is dropped to its base (`@Int`, `Option<Int>` beside `Option<PosInt>`), and a `@Nat` beside an `@Int` is an `@Int` at every position, a non-negative literal with no subtraction beside a `@Nat` at the top still making a `@Nat`.  Binding such a join where the refinement is expected is the narrowing it is, obligated by its arms.  This closes silent false proofs, where an `ensures` read `verified` and the run broke it: a `Box<Int>` beside a `Box<PosInt>`, a `Result<Int, Int>` beside a `Result<PosInt, NegInt>`, an `Err(@Int.0)` beside a `Result<PosInt, NegInt>` and a `Tuple<Int, Option<Int>>` beside a `Tuple<Int, Option<PosInt>>`, each through a generic function; a join of joins with a `@NegInt` arm; a `State` handler inside an `Exn` handler whose clause yields an `@Int`; and an `Exn` handler whose clause is `@Nat.0 - 1` beside a `@Nat` body, which proved `ensures(@Int.result >= 0)`.  Two reports change: a generic call over such a join, `idg(if @Bool.0 then { @Int.0 } else { @PosInt.0 })` under `ensures(@Int.result > 0)`, is instantiated at `@Int`, so the `ensures` is checked at run time (`E522`) in either order, where with the `@Int` arm first it read `verified` beside an `E505` at the argument; and a `let @PosInt` bound to such a join keeps its post-fact, so an `ensures` over the binder is `verified`, where with the `@Int` arm first it was refuted (`E500`) at an input the bind's guard traps on first.  One proof becomes a run-time check: a join of a literal and a refined value passed to a generic function with no expected type is instantiated at the base type, so a contract over the result that was proved is checked at run time (`E522`, or `E506` at a refined `let`); bind the join at the refined type first, then pass the binding.
