- An index into an array whose element type nothing fixes is refused at `vera check` (`E164`) ([#1862](https://github.com/aallan/vera/issues/1862)): `match [][0] { _ -> 1 }`, `[][0] + 1`, `"\([][0])"`, `let @Array<Int> = [[][0]];`, `Tuple([][0], 1)` at a typed binding, `let @Int = identity([][0]);` with `identity` a `forall<T>` function, `Box([][0])` with `Box` a constructor of a data type with no type parameters, and `@Array.0[0]` over an `Array` written with no type argument.  `vera check` accepted each with no diagnostic, `vera verify` warned that code generation skipped the function (`E602`), and `vera run` refused it (`E907`).  An index into the result of a generic call whose type variable no argument fixes (`empty(())[0]`) is not refused: the variable is instantiated at the phantom type (spec §11.4.1), and the index traps where it is evaluated, as an index into any empty array does.  A type reaches the index from a typed `let`, a function's result, a typed `if` branch, the argument of a function with no type parameters, and a generic constructor's argument where the constructor's type is expected (`let @Option<Int> = Some([][0]);`), and these check as before; an array literal's element, a `Tuple` component, any generic function's argument, a non-generic constructor's argument, an operand, an interpolated value and a `match` scrutinee type the index on their own first (spec §4.12.2).  The fix names the type to write: bind the array at its type first (`let @Array<Int> = [];`) and index the binding, or index it where a type is expected (`let @Int = [][0];`).  A `match` or a destructuring `let` over such an index draws `E164` alone, where it drew `E313`; a `match` or a destructuring `let` over a value a typed hole leaves unknown (`match ? + 1 { 1 -> 1 }`, `let Tuple<@Int, @Int> = ? + 1;`, `match Tuple([?][0], 1) { Tuple(1, _) -> 1 }`) draws the hole's `W001` alone, where it drew `E313` or `E311` beside it.
- `old()` and `new()` naming an effect with no state (`old(IO)`, `new(Exn<Int>)`) are refused at `vera check` (`E189`), as spec §7.9.2 requires ([#1862](https://github.com/aallan/vera/issues/1862)).  `vera check` accepted them, and `vera verify` stopped with an internal error (`E699`).  The fix names the `State` cell to write as the function's row writes it (a refinement alias by its name, `old(State<Positive>)`), and the row entry to declare where the function has none.
