- **A contract predicate is held to purity, whatever its function's effects clause names (breaking)** ([#1708](https://github.com/aallan/vera/issues/1708)).  A contract was checked under its function's row, so `requires(Random.random_int(1, 1) > 0)` under `effects(<Random>)` passed check and verify, and the compiled precondition performed the operation; a refinement predicate on an alias, a data field or a signature was held to no row at all.  Spec §7.9.1 holds every contract predicate to purity, and the checker now refuses, with `E187`, each place in a `requires`, `ensures` or `decreases` clause, an `assert`, an `assume` or a refinement predicate that performs an effect: an effect operation, a call to a function whose effects clause names an effect, an `apply_fn` of a function value whose type names one, and an anonymous function written in it whose body performs one.  A handler written inside the predicate handles its own instance of the effect there, so what it handles is accepted, and so are `old` and `new`.  A program whose contract performed an effect is refused: perform the operation in the body, bind its value with `let`, and check that value with `assert`.  No program in `examples/`, `tests/conformance/` or the documentation's Vera blocks changes its verdict.
  - Under `effects(pure)`, an operation in a contract is `E187` at the operation, where it was `E122` at the function; under a row that does not name its effect it is `E187`, where it was `E125`.
