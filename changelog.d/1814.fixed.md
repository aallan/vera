- What a type states of a value is assumed at every position the solver reads ([#1814](https://github.com/aallan/vera/issues/1814)): an `Int`'s i64 range and a `Nat`'s `0 .. 2^63 - 1` at the head and inside a data value, a tuple or an array element, a refinement over a data type inside a type, and a recursive type's positions to a bounded depth, of every parameter, refinement binder and stand-in.  `let Tuple<@Int, @Int> = @Tuple<Nat, Nat>.0` under `ensures(@Int.result >= 0)`, an `Array<Nat>` element's sign and `ensures(@Int.result <= 9223372036854775807)` on the identity are proved where they were refused (`E500`) with counterexamples no value of the type has, and the `int_overflow` rows of `@Int.0 + 0` and `@Int.0 * 1` are proved.  A refinement over a data type is decided where a value is given the type: `code_e(Red)` against a parameter of `type NotRed = { @Color | @Color.0 != Red }` is refused (`E505`) where it was a runtime check (`E506`), and `code_e(Green)` is proved.  **Breaking:** a `requires` that admits only values outside what a parameter's type states (outside the i64 range, or an `Array<Nat>` element below `0`) admits no argument and is refused (`E538`); no example, conformance program or documentation block has one.  **Breaking:** a refinement over a data type whose predicate calls a helper with no postcondition stating its value (`{ @Tuple<Int, Int> | fst(@Tuple<Int, Int>.0) > 0 }` with `fst` ensuring `true`) refuses (`E505`) a value that satisfies it, where it was a runtime check, as `{ @Int | g(@Int.0) > 0 }` with `g` ensuring `true` already did; no example, conformance program or documentation block has one: give the helper the postcondition that states its value.
