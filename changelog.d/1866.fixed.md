- **Breaking: a sibling branch's or arm's type fixes no variable a call leaves open, through whatever part of it reaches the call, and the order of a join's arms never decides a verdict** (spec §5.9, [#1866](https://github.com/aallan/vera/issues/1866)).  An `if` branch or a `match` arm whose type a call leaves open is checked again against its sibling's type so that a constructor can take its type arguments from it, and the check told that type from one the context gives by comparing type objects.  An index hands its call the element type wrapped in a new `Array`, so `idg(match @Bool.0 { false -> @Int.0, true -> empty_ord(())[0] })` was accepted with `empty_ord` at the other arm's `Int`, and was refused (`E613`) with the arms swapped.  The same happened through a block's result and through a nested `if` or `match`.  A callee's parameter, a `let`, a closure's return, a handler's state, an `==` operand and a constructor field fixed by another argument hand a call a type of their own, but where that type was the same shared `Int` object as a part of the sibling's type the call was refused inside a branch (`E613`, `E170`, `E171`, `E213`) and accepted outside one: `take(head_ord([]))` beside a `Tuple<Option<Int>, Int>`.  A sibling's `Nat` also gave a literal its type, so `Tuple(None, idg(0 - 3))` beside a `Tuple<Option<Int>, Nat>` was refuted (`E503`).  Each of these held in three arm orders of four, the fourth being a `match` with the open arm first.  Each type handed down now says where it came from: a part of a sibling's type keeps that origin through every wrapper, and every other type is the context's, so a branch is judged as the same expression is outside one, in every order.  The calls a parameter, binding, return or state types are accepted, and the literal is placed at `Int`.  **Breaking** for an indexed, block-result or nested-join call that nothing but its sibling gives a type, which `vera check` accepted in an `if` and in a `match` with the sibling arm first: it is refused with `E613`, whose fix writes the binding where the call is, `let @Array<Int> = empty_ord(());`, then `@Array<Int>.0` in its place.  No example, conformance program, documentation example or benchmark solution changes verdict.
