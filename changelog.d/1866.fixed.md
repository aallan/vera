- **Breaking: a sibling branch's or arm's type is no type a value is expected at, so the order of a join's arms never decides a verdict** (spec §5.9, [#1866](https://github.com/aallan/vera/issues/1866)).  An `if` branch or a `match` arm whose type a call left open was checked again against its sibling's type, and the check told that type from one the context gives by comparing type objects.  An index wrapped it in a new `Array`, so `idg(match @Bool.0 { false -> @Int.0, true -> empty_ord(())[0] })` was accepted with `empty_ord` at the other arm's `Int` and refused (`E613`) with the arms swapped; a callee's parameter that was the shared `Int` object was taken for the sibling's, so `take(head_ord([]))` beside a `Tuple<Option<Int>, Int>` was refused in a branch and accepted outside one; a sibling's `Nat` placed a literal at `Nat` (`E503`); and a constructor's field expectation carried the sibling's type into the constructor's inference, so `MkW(None, head_ord([]), None)` beside a `W<Int, Int>` was accepted in three orders and refused in two.  Each arm is now synthesized once, against the type the join's context expects, and the join completes in an arm's recorded types only the variables its constructors left open, never one a call's instantiation holds: a branch is judged as the same expression outside one, in every order.  **Breaking** for a call that nothing but its sibling gives a type, accepted in some orders: it is refused with `E613`, whose fix now writes the binding as a block in the call's place, `{ let @Array<Int> = empty_ord(()); @Array<Int>.0 }`, so no later read of a slot of that type reads it, and writes it only where each type name in it resolves where the call is.  **Breaking** too: `array_length([match @Nat.0 { 0 -> Tuple([1], []), 1 -> dup(None), _ -> Tuple([2], ["s"]) }])`, with `forall<T> fn dup(@Option<T> -> @Tuple<Array<T>, Array<T>>)`, was accepted in one arm order of three and is now refused (`E302`) in all three, as its literal and `if` forms already were: `dup`'s two arrays are one type, which the first arm makes `Array<Int>`.  The refusal of `if @Bool.0 then { None } else { Some(3) }` as the body of a `forall<T> fn (@Bool -> @Option<T>)` moves from `E121` to `E301`, the code for branches of incompatible types.  No example, conformance program, documentation example or benchmark solution changes verdict, and no compiled module changes.
