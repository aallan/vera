- The documents, the specification and the diagrams say what the compiler does.  Each statement a command can check was run against 0.2.8, and about 140 were wrong.  `README.md` said a quantified `ensures` gets no runtime check, where the contract code generation does not lower is an `ensures` over a `String` or `Array` result, disclosed as `E543`; `vera verify examples/safe_divide.vera` verifies 9 obligations, not 6; the warnings that disclose an obligation nothing guards are `E504`, `E506`, `E539`, `E540`, `E542` and `E543`; `SKILL.md` said `Tuple<>` is `Unit`, which is a parse error, and `FAQ.md` that `Bool` is `Ord`, which is `E242`; `TESTING.md` now documents the envelopes `vera compile --json` and `vera run --json` print; `MUTATION.md` gave the sweep's state schema as 2, which is 3; and `vera/README.md` named functions that do not exist.
- The specification no longer contradicts itself or the reference compiler where a sentence was overruled by another section or by what runs:
  - §2.8 rule 5 states the variance the checker implements: a data type is covariant in its type arguments (`Array<PosInt> <: Array<Int>`), and a function type is contravariant in its parameters and covariant in its result and its effect row (§7.8).  It said compound types have no variance.
  - §5.9 follows §4.2: the type a result is expected at fixes a type argument whatever the literals' signs.
  - §2.1 says a `let` declares its type, as §4.7 and the grammar do.
  - §3.7 defines `@Fn`, the name every binding written with a function type shares, and §3.3 and §3.10 list closure parameters and handler state as binding sites.
  - §5.5, §5.9.1 and §7.6 bind the effect variable their examples use, so the `E340` they describe is the error the compiler gives.
  - §5.4 drops the note it said the compiler SHOULD emit for `requires(true)` and `ensures(true)`, which are the canonical spelling of a function with no precondition and no postcondition.
  - §9.1.2 lists the eight prelude data types §8.4.1 reserves.
  - §11.1 describes the pipeline as it runs (`vera compile` does not verify, and code generation reads the typed program), §11.4.2 the registration passes, §11.11.2 how a handler clause is compiled, §11.8 which contract has no runtime check, and §11.2.1 the refuted `@Nat` subtraction (`E502`).
  - §12.2.2 lists every host import, where it listed 39 of them, and the `State` cell tables include compound, `data` and `Map` cells.
  - §0.5.8, §1.8 rule 11, §6.8, §10.1, §12.3.2, §12.4.1, §12.9.3 and §13.8 are corrected in smaller ways.
