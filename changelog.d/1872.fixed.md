- The command line is read against one table of what each command takes (`vera/command_line.py`), so an option is taken by exactly the commands that list it ([#1872](https://github.com/aallan/vera/issues/1872)).  `vera check good.vera bad.vera` printed `OK: good.vera` and exited 0 without reading `bad.vera`, and `vera verify` and `vera fmt --check` did the same; a command that reads a program now reads exactly one file, and a second is refused (`E904`) before either is read, its fix to run the command once for each file.  A flag a command does not take (`vera parse --json`, `vera fmt --json`, `vera check --wat`, `vera verify --fn f`, `vera lsp --json`) was ignored, and an unknown one was read as the file when it came first (`E900`, `file not found: --bogus`) and ignored after it; each is refused (`E901`), naming the commands that take it.  A flag after `--` was read as the command's own (`vera run f.vera -- --json` printed the envelope and passed `--json` to the program); under `vera run` every token after `--` is now the program's argument whatever it looks like (`-1`, `--5`, `-`, `--json`), and `--` on any other command is refused (`E901`).  A valued option with no value (`vera compile f.vera -o` wrote `f.wasm`) or with a value the command does not take (`vera run --target browser`, which ran under the core target) is refused (`E903`), and an option given twice, which took the first value, is refused whatever the two values are (`E902`).  Each valued option has a domain, and a value outside it is refused (`E903`): `vera test f.vera --trials 0` (or `-5`) printed `Testing:`, ran no trial and exited 0, and a count of trials is now a positive integer; `--port` is 0 to 65535; `--fn` is a function's name; and `--timeout-ms` and `VERA_Z3_TIMEOUT_MS` are at most 4294967295, past which Z3's unsigned budget wrapped silently (`2**32 + 1` ms was 1 ms); the flag comes first in the budget's precedence, so `VERA_Z3_TIMEOUT_MS` is read and validated only when `--timeout-ms` is absent, where a malformed value in the environment refused `vera verify --timeout-ms 1000`.  A valued option followed by another option has no value (`E903`), where `vera run f.vera --fn --json` looked for a function called `--json` (`E906`).  The `--name=value` form is refused (`E901`) with a fix that writes it with a space, where `--fn=add` and `--target=browser` were ignored.  A file whose name begins with a dash is named `./-name.vera`, and the refusal of `-name.vera` says so.  An empty operand or a directory, which were the internal-error code (`E699`), is `E900`.  The options a command refuses together are `E902`: `vera fmt --check --write`, which exited 0 and only checked, `vera compile --wat -o` and `vera compile --wat --target browser`, which printed the core module's text and wrote nothing, beside `vera verify --reconcile --no-reconcile` as before.  `vera lsp` lists `--stdio`, the flag editors pass by habit, since stdio is its one transport.  `vera builtins f.vera` and `vera version extra` ignored the operand, and are refused (`E904`).  `vera <command> --help` and `-h`, which reported `file not found: --help`, print the command's usage on stdout and exit 0, and `vera --help` and `vera -h`, which were `E904`, print the usage the same way; the usage text and each command's help are rendered from the table, which also renders a new table of the commands and their options in `TOOLCHAIN.md`.  A command-line refusal is the `--json` envelope on stdout when `--json` stands before any `--`, and the diagnostic on stderr otherwise, exit 1 either way.  Spec §0.5.8 now lists every command the table gives `--json`: `vera ast`, `vera builtins`, `vera effects` and `vera errors` beside the five it named.
  - **Breaking**: each of these exited 0 and now exits 1: a command line that names a second file; one with an option its command does not take, `vera parse --json`, `vera fmt --json` and `vera serve --json` among them; a token after `--` on any command but `vera run`; `vera run --target browser`; a valued option with no value, or given twice; an operand to `vera version`, `vera lsp`, `vera builtins`, `vera effects` or `vera errors`; `vera test --trials 0` and any `--trials` below 1; a `--port` outside 0 to 65535; a `--timeout-ms` or `VERA_Z3_TIMEOUT_MS` above 4294967295; a `--fn` that is not a function's name; the `--name=value` form; `vera fmt --check --write`, `vera compile --wat -o` and `vera compile --wat --target browser`.  A command line that was `E906` or `E699` for these is now `E903` or `E900`, exit 1 as before.  Run a command once for each file, and drop the option, or give it to the command `vera <command> --help` shows takes it.  `vera run f.vera -- --json` no longer turns on the envelope: put `--json` before the `--`.
