- **The program generator, version two, and a fourth differential.** `tests/program_generator.py` writes recursion with `decreases` (a `@Nat` measure its `requires` bounds, a mutual pair through a `where` helper, and a structural measure over a recursive data type), generic helpers called only at types their `where` clause admits, plain and refinement type aliases at a slot's head and inside a type argument, a module beside the entry that the entry imports by a selective list of what it uses, `Array`, `Map`, `Set` and `Tuple` values with their readers (`array_length`, an index under the bound that proves it, `array_fold`, `map_get`, `set_contains` and `set_size`), `handle[State<Int>]`, `handle[State<Nat>]` and `handle[Exn<T>]` with `throw`, and `State` and `Exn` helpers called under them, and pairs of parameters of one type under the non-commutative operators, whose `ensures` holds for the operands' order the generator meant and not for the other; every contract is still true by construction.  `tests/test_program_generator.py` holds each program to a fourth differential: the program and four edits of it (a literal moved inside its interval, a `let` added, a pair's operands swapped, a function added with a call to it, a `requires` tightened, a contract broken and restored) go in order to one warm `VerificationSession`, as the language server sends a document's text, and each text alone to a fresh session, and the two must report the same obligations, with the same statuses at the same places, and the same diagnostics.
  - `KNOWN_CLASSES` counts version one's two `nat_bind` classes as the one mechanism of [#1695](https://github.com/aallan/vera/issues/1695) they are (a value the declarations make non-negative, which code generation's declared-name rule does not read as one), and adds three of #1695's that version two's shapes meet: a narrowing into a refinement of `Nat`, recorded once and checked twice; a refinement check on a value the declarations already give the refinement; and a join of a refined arm with an unrefined one, which the checker types as the refinement.  Each predicate reads the program as written, never the checker's tables.
  - Two counterfactual classes count the finds code generation makes by reading a value's type off the expression rather than the checker's types.  A find of the load, reconcile or distrust differential that vanishes with each fold and each argument at a generic's type variable bound in place by a `let` of the type the checker gives it (a fold's being its initial value's) is [#1525](https://github.com/aallan/vera/issues/1525)'s, and one that vanishes once each handler a branch takes is bound too is [#1744](https://github.com/aallan/vera/issues/1744)'s; a find that does not vanish is reported.  The generator writes those shapes: an arithmetic argument at a type variable, a fold as a scrutinee or a constructor's argument, and a branch whose every arm is a fold, a `throw` or a handler.
  - A warm find whose two sessions differ in a counterexample alone is counted under [#1785](https://github.com/aallan/vera/issues/1785), with no pin: the model the solver returns depends on the solver work the process did before.  The night's report gives each known class its count, its programs and its first seeds.
  - The generator models as unconstrained what the verifier does not translate ([#1696](https://github.com/aallan/vera/issues/1696)): a generic's call, a fold, a cell's read, an element and a handler's value, an array literal holding a generic call's result, whose length it knows nothing of, a `match` on a constructor applied in place or on `map_get`'s result, and a call taking a value it has no term for (a constructor of the module's data type among them), whose `ensures` it drops.  A fold takes its initial value's type, as the checker gives it, and the `nat_bind` class counts a fold from a `@Nat` bound to a `@Nat`, which the module guards with no record.
  - `.github/workflows/nightly-generator.yml` runs 1,900 seeds a night, where it ran 5,000: on the runner a version-two program with its edits takes 0.92 s, 4.3 times a version-one program's 0.213 s.  Every pull request runs ten pinned seeds that between them write every construct of the grammar.
