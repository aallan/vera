- **The suite runs the pipeline in process, and a test starts a process only where the process boundary is what it measures.**  A helper that read a `--json` envelope reads the stage's envelope through `tests/pipeline.py`, and every other crossing of the CLI, a read of an exit status, of stdout or stderr, of `--wat`, of `run` or `test` output, or a call passing an option besides `--json`, runs `vera.cli.main` in process through `pipeline.cli`.  Every assertion on an exit status or on stderr text that a test made of a process it now makes of `pipeline.cli`'s result.
  - Measured by one sample-mode run of the base and one of this change, back to back on a 12-core Mac (`python -m pytest -n auto -p tests.subprocess_census --matrix-seed=2026-W42`), with a Backblaze upload running on one of the twelve cores during both halves: 21,286 tests, 6,264 worker-seconds and a 74.2% subprocess share at the base, against 21,309 tests, 2,568 worker-seconds and a 37.1% share with this change.  The files it does not touch took 1,870 and 1,843 worker-seconds in the two halves.  Run alone, `tests/test_conformance.py` went from 67.4 s of wall time to 6.6 s, and `tests/test_boundary_guard_correctness_1466.py` from 50.9 s to 3.5 s, or from 230.9 s to 8.8 s with all 991 cells.
  - `tests/test_conformance.py`'s check, verify and negative stages read the stage results, and its run stage runs `vera run` in process on an empty stdin and the run environment, comparing the bytes it writes with each entry's `expected_stdout` and `expected_exit` as before.  A run still going after `RUN_TIMEOUT_SECONDS` ends the worker through `faulthandler`, and pytest-xdist reports the test it was running.
  - `CLI_SMOKE` in `tests/test_conformance.py` names ten corpus programs that run through `python -m vera.cli` as a process: 18 cells over every command that takes a program and both exits the corpus has, each holding the exit status and both streams' bytes to the in-process CLI's.
  - `pipeline.cli` writes to streams that write as a process's text-mode stdout does, and `CliResult` carries `stdout_bytes` and `stderr_bytes` beside the text.
  - `scripts/check_test_drivers.py`'s allowlist goes from 46 entries to 21.  The 32 helpers that ran the CLI as a process leave it, bar the smoke's driver and six that keep a process under a reason naming what the boundary measures: two `PYTHONHASHSEED` sweeps, programs whose unrooted wrapper faults the host, programs that never stop unless the guard under test stops them, a deadline that is the assertion, and a scratch copy of the compiler.
  - `scripts/render_status.py`'s `conformance_skips` stubs the pipeline, so reading the skipped-stage table no longer starts a `vera run` for every run-level entry.
  - `tests/test_nonregular_data_rejected_1429.py`'s linked-against-flat timing ratio no longer carries a process start-up on each side, and takes the fastest of three checks after an untimed one.
  - `pyproject.toml` has coverage measure a test's child Python processes (`[tool.coverage.run]`, `patch = ["subprocess"]`), so the smoke's processes count.
